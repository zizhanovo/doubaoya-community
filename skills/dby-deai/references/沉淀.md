# 沉淀：把判据的缺口记下来

用户手改了你的改写、或者说你哪条建议不对——那是**判据的缺陷**，不是这次会话的插曲。
不记，下次原样再犯一遍。

## 什么时候记

只在两种情况：用户明确说「记下来 / 以后别这么改」；或者那明显是通用规律而不是一次性口味。
**一次会话的个人偏好不记**——记多了会长成新的规则腔。

## 记到哪

**用户工作区**的 `deai-偏好.md`（不是本包目录）。

⚠️ 包内文件会被 `dby-update` 对账覆盖，写回包里下次更新就没了。
用户工作区不会——代价是他换个项目就带不过去，所以文件要小、要能直接复制。

## 格式（脚本要读，别改结构）

```markdown
# deai 偏好

## 豁免
- 首先
- 其实
- 说白了

## 改法
- 他的「不是A而是B」大多是真对比，别拆
- 结尾允许一句收束，但不许升华到价值观

## 触发
- 「这段读着别扭」= 要体检，不是要改写
```

**「## 豁免」一节是机器读的**，一行一个 `- 词`，脚本会跳过这些词的命中：

```bash
python3 scripts/deai.py 稿件.md --profile deai-偏好.md
```

报告里会写「已按 deai-偏好.md 豁免 N 处」——**豁免要留痕**，不能悄悄少报。

另外两节是给你（agent）读的：动手前扫一眼，改写时照办。

## 三类各归各位

| 发生了什么 | 记进哪一节 |
|---|---|
| 你报了一处，用户说「这是我一直的写法」 | 豁免 |
| 用户手改出来一个你没想到的改法 | 改法 |
| 一句话触发错了档（他要体检你去改写了） | 触发 |

## 上游

在维护者手里，这三类分别对应包内的 `病灶清单.md` 的「不算」栏、`改法.md`、
`evals/triggers.jsonl`。**用户侧的 `deai-偏好.md` 攒够了就该往上游搬**——
那才是「集体经验」和「个人口味」的分界线。
