# 文风锚定

**什么时候做**：用户说「改得像我写的」「按我的风格」「别改成别人的腔调」。
只说「去 AI 味」不做——那是删共性，这是保个性，两件事。

## 一、先拿到样本

按这个优先级，拿到就停：

1. **`dby-charter` 的创作 DNA**——已经从用户范文里蒸好的文风特征卡，最省事：
   `dby charter get`（CLI）或 `node <dby-charter>/scripts/charter.mjs get`。
2. **用户直接给 2–5 篇代表作**，每篇 200–800 字。
3. **用户工作区里的既往定稿**（他自己发布过的）。

样本三条纪律：**别混两种文风**（公众号和周报不是一个人格）；**别喂初稿**，要发布后的定稿；
**覆盖面比数量重要**——三篇不同题材胜过十篇同题材。

## 二、把样本压成他自己的基线

```bash
python3 scripts/deai.py --make-baseline 范文1.md 范文2.md 范文3.md > 基线.json
python3 scripts/deai.py 稿件.md --baseline 基线.json
```

这是本包唯一诚实的阈值来源。中文侧**没有任何公开的实证阈值**（见 `病灶清单.md` §8 的警告），
拿通用数字卡人只会误伤——真人也说「首先」。作者自己的基线没有这个问题：
报告会直接告诉你「套话每千字 31，你平时 10.5，3 倍」，而不是「超过某个来路不明的线」。

句长那一行尤其要看：**标准差明显低于他平时 = 节奏被抹平了**，这是最难靠删词修回来的一项。

## 三、再提 3–6 条可编辑的特征卡

基线给的是数字，特征卡给的是写法。从样本里读出来，**不要用形容词描述语气**
（「亲切自然」不可执行）：

- **人称与称呼读者的方式**：他叫「你」还是「大家」，还是根本不称呼
- **举例的习惯**：用数字、用故事、用对话，还是直接甩截图
- **连接方式**：他靠什么把两段接起来（时间、转折、直接跳）
- **段落与小标题**：段落多长，小标题是问句还是陈述，用不用编号
- **口头禅与固定说法**：他真的反复用的那几个词
- **他从不用的东西**：样本里一次都没出现的词与句式，这条比前五条都值钱

## 四、锚定优先于本包所有规则

样本里长期这么写的，**就是他的文风，不算病灶**，报告里归进「可以不改」并说明依据是哪篇范文。
这条压过 `病灶清单.md` 的任何一条。

## 五、边界：锚定解决不了「像你思考」

有人拿 200 篇自己的文章去蒸文风，产出仍然「很像但没有人味」——**可模仿的是形式，
不可模仿的是经验、立场和取舍**。

所以：文风锚定解决「像你说话」，`加人味.md` 的索料解决「像你思考」。
用户抱怨「还是不像我」时，先判断他缺的是哪一个——**缺后者时再怎么调锚定都没用**。
