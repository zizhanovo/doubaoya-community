# 结构审读

体检的第二遍。第一遍（脚本 + `病灶清单.md`）的工作单位是**句子**；这一遍是**整篇**。

为什么必须有这一遍：AI 写的东西「语义过渡过于丝滑」——顺滑本身就是它掩盖逻辑漏洞的方式。
读者说「一股 AI 味」时，有相当一部分指的不是用词，是这一层。逐句删套话永远碰不到它。

## 读的时候假装你只有这篇正文

不看作者的自述、不看他的检查清单、不看你们刚才聊过的背景。**作者知道的东西不等于正文写了**——
把背景带进来读，就会替他把缺的那句话在脑子里补上，然后觉得没问题。

## 四问

### 1. 标题承诺的和正文交付的，是不是一件事？

两个方向都要查：标题说的那件事正文兑现了吗；正文里最硬的那个东西，标题说了吗。

❌ 标题主打「只用一台 Mac」，可「Mac 能兑换」是常识、不构成信息增量；正文真正的发现是另一条路径。
✅ 标题指向那条真正稀缺的路径。

顺带查小标题体系：编号（第一步 / 第二步）只能用在**读者要执行的动作**上。
「第二步：常走的渠道挂了」不是步骤，是发生的事，编号会让读者以为要执行它。

### 2. 全文最硬的那一条，在第几屏？

找出唯一一条**不查就不知道、查了也不好查**的东西——那是这篇存在的理由。
然后看它的位置。埋在第四节的第 ④ 个小圆圈里，和「点头像进账户页」这种常识操作并列，就是埋了。

处置：**前移**，或者提到小标题里。不要靠加粗补救。

### 3. 每一条因果的依据，在不在场？

把正文里所有「因为…所以…」「X 导致 Y」「最好的办法是 Z」「这不是绝路，因为…」逐条抽出来，
逐条问：依据是什么，在正文里吗。

三种处置，**没有第四种**：
- 依据在场 → 放过
- 依据不在场，但作者手里有（他试过、他看到过报错）→ **标记，让作者补**
- 依据不在场，作者也没有 → 标记为**待核实**，让作者决定删还是改成不确定语气

🔴 **绝不许把依据不在场的因果直接删掉。** 删掉之后下游的结论会悬空——读者看到「付款失败 →
所以去买礼品卡」，中间那一跳没了，整条路径失去理由。这比留着一个没支撑的断言更糟。
（这条是 2026-08-31 的实账：改写档按「模糊归因补不上就删」执行，把一条支撑性因果删没了。
`改法.md` 第 8 条已据此加了例外。）

### 4. 照着做，能复现吗？（操作类内容才问）

列出所有**隐含前提**：环境、账号类型、地区、网络、版本、时机、前置操作。
逐条查它在不在正文里。

❌ 截图状态栏全程有 VPN 标识、付款页条款写着「仅适用于实际 IP 位于美国的账号」，正文一字未提。
✅ 前提写在第一步，读者判断得了自己能不能照做。

**前提不在正文里，教程就是坏的**——读者照着做会失败，而他不知道为什么。

## 两条附加检查

**分流点和它的依据有没有分家。** 文章早期给读者分流（「你属于 A 就不用往下看了」），
那个分流的判断依据必须当场给全。把「其实 A 那条路还便宜 25%」放在文章末尾，
等于让读者读完全文才发现自己不该走这条路。

**未核实的事实是不是用了确定语气。** 作者自己标着待核对、或你是从截图/上下文推出来的数字与名称，
正文不许写成确定陈述。要么核实，要么改成「当时看到的是…」这类可回溯的说法。

## 处置纪律

🔴 **结构问题默认只标不改。** 改结构 = 改作者的表达意图和事实主张，必须作者点头。
你能自己动手的只有 A/B/C 三层（`改法.md`），这一层的产出是**清单，不是改后稿**。

## 输出形状

接在体检报告的第三节，每条一行：

```
**不是文风问题**
1. [标题错位] 标题主打 X，但正文最硬的是 Y → 建议改标题指向 Y
2. [依据缺失] 第 12 句「最省事的解法是充余额」缺前提：为什么不能直接绑卡？
   → 你当时的报错是什么？补一句，别让我替你编
3. [前提缺失] 截图里有 VPN 标识但正文没提 → 是复现的必要条件，要写进第一步
4. [待核实] 「充了 $200 约 1350 元」是倒推的 → 核对实付金额，或改成不确定语气
```

一条都没有时，明说「结构审读没发现问题」——不要为了显得有产出而硬找。
