# 多平台文案改写 · wechat-rewrite

把一份原文改写成**某个平台读者习惯的样子**。支持七个平台，一次可以指定一个、几个或全部——
「一稿多发」就是这么来的：同一份原文，七个平台各出一版，而不是一版群发七处。

> 📌 **目录名比内容窄，这是笔明账。** 这个包由原来的公众号改写、小红书改写、多平台改写
> 三个包合并而来，沿用了 `wechat-rewrite` 这个目录名（它是站点详情页的挂钩，改名要多付两处映射）。
> **agent 匹配的是 description、不是目录名**，所以这只是命名债，不影响你把它当七平台工具用。

> ⚠️ **同名的两样东西，别混起来。** 都爆鸭平台上另有一条云端能力 `skill.wechat.rewrite`
> （catalog slug 也叫 `wechat-rewrite`，走 `POST /api/skills/wechat-rewrite/invoke`，**计费**）。
> 它与本 Skill 包**不是同一个东西**：本包是装到你机器上、由你的 agent 就地改写，不联网也不花钱；
> 那条能力是平台侧的云端调用。本文件同时被平台快照成那条能力的详情页正文，所以这里说明一句——
> **上面「纯本地、不联网」说的是本 Skill 包，不是那条云端能力。**
> （该能力当前在 catalog 里标着 `availability: hidden`、并未对外在售，`GET /api/skills/wechat-rewrite`
> 返回 `SKILL_NOT_FOUND`；哪天它重新上线，这段话正是防止详情页自相矛盾的那道说明。）

## 1. 怎么用（三步）

### 第 1 步：拿到原文和目标平台

用户说「把这段改成小红书风格」——原文是这段话，目标平台是小红书。
**用户没说平台就问一句**，别默认公众号：七个平台的调性差得很远，猜错等于白改。

### 第 2 步：读该平台的规则

🔑 **一平台一文件，读你要的那个就行，别整摞读。**

| 用户要哪个平台 | 读这份 | 这个平台的要害 |
|---|---|---|
| 公众号 / 微信公众号 | [`references/公众号.md`](references/公众号.md) | 金句 + 钩子；标题 **≤20 字**是硬规则；正文带 2–3 个 Keyword；末尾 5–10 个 `#` 标签 |
| 视频号 / 微信视频号 | [`references/视频号.md`](references/视频号.md) | 口播感，开头三秒抓人 |
| 抖音 / dy | [`references/抖音.md`](references/抖音.md) | 短平快、强节奏、强钩子 |
| 快手 / ks | [`references/快手.md`](references/快手.md) | 接地气、短小精悍、直给 |
| B站 / 哔站 / bilibili / 哔哩哔哩 | [`references/B站.md`](references/B站.md) | 社区黑话与弹幕感 |
| 小红书 / 红书 / xhs | [`references/小红书.md`](references/小红书.md) | **至少 5 个不重复 emoji**；二极管标题法；种草口吻；末尾 `#` 标签 |
| 知乎 / zhihu | [`references/知乎.md`](references/知乎.md) | 论证感、有理有据、克制 |

每份规则的结构都一样：`Role`（角色定位）/ `WritingSkills`（写作技巧）/ `Rules`（改写规则）/
`Workflow`（工作流程）。**照着 Workflow 走**，别只扫一眼 Role 就动笔。

也可以让脚本把规则打出来（脚本读的就是上面这些文件，**不是另一份副本**）：

```bash
python3 scripts/rewrite.py list                  # 七个平台和它们的别名
python3 scripts/rewrite.py 小红书                 # 单平台规则
python3 scripts/rewrite.py 抖音,知乎 "原文…"       # 多平台（逗号或空格分隔都行）
python3 scripts/rewrite.py all                   # 全平台（一稿多发）
```

### 第 3 步：直接输出改写结果

按该平台的 Workflow 改写，**直接给成品**。

## 2. 通用纪律（七个平台都适用）

- **以文案发起者的身份写**：用户的文案就是你的文案，你只做风格转换。
  ❌ 不要说「帮你改写了」「以下是改写后的版本」，直接出成品。
- **只改风格，不改事实**：产品参数、价格、功效、时间地点一律照搬原文。
  改写是换说法，不是编新内容——编出来的卖点会变成用户的虚假宣传。
- **不反问、不确认**：输出完就结束，别再问「需要调整吗」。
- **多平台时逐个平台各出一版**，别出一版说「通用」——那就退回成没改写。

## 3. 目录结构

```
wechat-rewrite/
├── SKILL.md              # 本文件：入口 + 按平台分流
├── README.md             # 用户文档
├── references/           # 🔑 平台规则，一平台一文件（脚本与 agent 读的是同一份）
│   ├── 公众号.md
│   ├── 视频号.md
│   ├── 抖音.md
│   ├── 快手.md
│   ├── B站.md
│   ├── 小红书.md
│   └── 知乎.md
└── scripts/
    └── rewrite.py        # 平台别名解析 + 取规则（纯标准库，零网络调用）
```

**为什么规则不是一个大文件**：`references/<平台>.md` 同时是**给你直接 Read 的**参考资料和
**脚本的数据源**。合并成一个大文件就得两边各存一份（会漂），或者让脚本去切章节——
合并前那版正是靠章节标题模糊匹配来切的，平台名互为子串时随时会切错。
一平台一文件之后，脚本那里是一次精确查表，你这里是一次 Read。

## 4. 常见问答

**Q：需要装什么依赖 / 要 key 吗？**
A：都不要。Python 3 标准库，纯本地运行，全程零网络调用。

**Q：用户只说「改写一下」没说平台？**
A：问一句。七个平台调性差很远，猜错等于白改。

**Q：能一次出七个平台的版本吗？**
A：能，`python3 scripts/rewrite.py all`，或者直接七份 references 都读了逐个改。
这就是「一稿多发」。

**Q：改写会不会把产品参数改错？**
A：不该会——**只改风格不改事实**是纪律。参数、价格、功效照搬原文，这条比任何风格规则都优先。
