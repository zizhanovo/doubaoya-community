# 模式 B 的导航图（来源 skill × 结论信号 → 下一步）

> 只在**本次对话里已经有某个本鸭 skill 的输出**（选题表、爆文清单、草稿、诊断报告……）、
> 要决定下一跳走哪个包时读它。任务前路由（模式 A）用 SKILL.md 的路由表，不必读这份。

### 导航图（来源 skill × 结论信号 → 下一步）

#### 选题阶段 —— 来自 `dby-api`

| 结论信号 | 推荐下一步 | 为什么 |
|---|---|---|
| 选题定了，要动手写 | `dby-write` | 主干从这里接手；需要爆文样本时它自己回头调 `dby-api` |
| 想让文章更像你本人 | `dby-charter` | 动笔前先备好创作 DNA（档案那半边），写时全程读它 |
| 有现成旧稿想复用这个角度 | `dby-rewrite` | 本地改写成公众号爆款风 |
| 选题还模糊，想先看爆款规律 | `dby-api` | 同主题爆文里找共性再定选题 |

> 🔑 **「我这个号今天该做什么选题」的正确三步**（原综合热点选题包那套玩法，包合并后由本图承接）：
>
> 1. **无关键词直取综合热点** —— 走 `dby-api` 的 `api.trend.hotSpotKeyword`，把当下全网最热的
>    一批直接拉下来。要害是**不带关键词**。
> 2. **明确个人 IP 定位** —— 用户的账号名 / IP 名（比如「菜籽油」）是**他是谁**
>    （领域 / 人设 / 角度 / 受众），**不是搜索词**。从用户本人或其简介、往期爆款里拿到这份定位；
>    **不清楚就直接问他**：「你这号平时做什么内容、面向谁、你的独特视角是什么？」
> 3. **智能匹配** —— 拿第 1 步的热榜 × 第 2 步的 IP 定位，挑出这个 IP **能可信借势**的 2–3 条。
>    两条判据一起看：**热度**（够热、最好跨平台撞榜）与 **IP 契合度**（以这个人设的真实视角
>    接不接得住——接不住的哪怕再热也先放掉）。每条给出**这个 IP 的独家切角**，
>    再答一句「为什么现在能爆」。
>
> ❌ **绝不把 IP 名字丢进搜索接口。** 搜「菜籽油」只会搜到字面同名内容，跟这个号该写什么无关。
> IP 只用在第 3 步的匹配筛选上。这是这条路最常见、也最贵的一个错。

#### 写草稿阶段 —— 来自 `dby-write` / `dby-rewrite` / `dby-charter`

| 结论信号 | 推荐下一步 | 为什么 |
|---|---|---|
| 正文定稿，要起标题 | `dby-api` | 标题定打开率，专项拉套路优化 |
| 要封面**套路参考**（先看别人怎么做） | `dby-api` | 找同赛道封面配色 / 构图套路，给的是数据不是图 |
| 要**真出一张**封面图 / 插图 / 主视觉 | ⛔ 无 | 生图能力已因合规要求整体下架，无替代包；如实告知，改用你自己 agent 的生图工具或用户自备图片 |
| 怕正文踩违禁词 | `dby-banned-words` | 三平台一次比对，出全平台安全改写版 |
| 初稿读着一股 AI 味 | `dby-deai` | 逐句指出哪里像 AI，改不改由用户定 |
| 正文 + 素材都齐，要排版存草稿 | `dby-publish` | md→公众号 HTML→封面→草稿一条龙 |

#### 排版素材阶段 —— 来自 `dby-api`

| 结论信号 | 推荐下一步 | 为什么 |
|---|---|---|
| 标题 / 封面 / 合规都齐了 | `dby-publish` | 素材齐，进流水线排版 + 存草稿 |
| 就差一张图（封面或正文插图）| ⛔ 无 | 生图能力已下线；只能用用户自备或 agent 自己生图工具产出的本地文件，再进 `dby-publish` |
| 对默认排版样式不满意，想先改配色 / 标题 / 主题 | `dby-theme` | 改 themeJson→预览→存回服务端默认 + 落一份本机 theme 文件，发文时 `--theme` 指过去 |
| 合规检测发现要重写 | `dby-rewrite` 或 `dby-write` | 违禁词太多，回去改文案再来 |

#### 代发阶段 —— 来自 `dby-publish`

| 结论信号 | 推荐下一步 | 为什么 |
|---|---|---|
| 草稿已存，发布后想看表现 | `dby-api` | 攒几天数据给号做体检 / 看发文表现（`skill.wechat.accountAnalyzer`） |
| 想盯自己或竞品的发文节奏 | `dby-api` | 先 `api.gzh.searchUser` 拿账号 ID，再 `api.gzh.workList` 拉时段发文做追更复盘 |
| 已发文想归档正文 | `dby-api` | 按文章链接拉正文（`tool.content.parseDetail`） |

#### 复盘 → 反哺 —— 来自 `dby-write`（复盘模式）或 `dby-api`（账号诊断 / 发文列表）

| 结论信号 | 推荐下一步 | 为什么 |
|---|---|---|
| 想复盘自己已发的文章 | `dby-write` | 复盘模式：拉已发文章指标，按自身历史均值定四象限 |
| 复盘看清受众爱看啥，回去挖下一个选题 | `dby-write` | **飞轮闭环**：结论已落库，下一轮写作第 1 步会自动读到 |
| 发现自己号偏弱，想找对标学 | `dby-api` | 对标补短板、搭竞品矩阵（`skill.wechat.similarAccount`） |
| 想盯行业头部动态 | `dby-api` | 头部榜看赛道趋势：`POST /api/apis/gongzhonghao/gongzhonghao-index-rank/call` |
| 想深挖某条爆文为什么火 | `dby-api` | 拆同主题爆款规律 |

#### 对标 → 反哺 —— 来自 `dby-api`（对标推荐 / 头部榜）

| 结论信号 | 推荐下一步 | 为什么 |
|---|---|---|
| 找到对标，想扒它的选题角度 | `dby-api` | 对标有了，回选题挖角度 |
| 想持续追这个号的发文 | `dby-api` | 长期盯梢做复盘：`POST /api/apis/gongzhonghao/gongzhonghao-work-list/call` |
