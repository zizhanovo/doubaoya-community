# 输出模板：对照表与安全改写

> 交付时才读这份：拿到 `dby banned check` 的 JSON map 后，按这里的两段模板输出。
> 判定判据与错误读法在 SKILL.md（「每个平台怎么判有没有命中」「错误处理」两节）。

`dby banned check` 返回的是 JSON map，本鸭须解析后填入下面的模板，**禁止把原始 JSON 直接甩给用户**。

## 1. 逐平台风险对照表

| 平台     | 判定             | 风险类别 (prohibitedWordsType) | 命中词（从 content 的标注提取） | 建议（本鸭给）     |
| -------- | ---------------- | ------------------------------ | ------------------------------- | ------------------ |
| 小红书   | 【命中 / 无命中 / 检测失败】 | 【类别，逗号分隔】 | 【命中词，逗号分隔】            | 【替换建议】       |
| 抖音     | 【…】            | 【…】                          | 【…】                           | 【…】              |
| 公众号   | 【…】            | 【…】                          | 【…】                           | 【…】              |

- 平台名用中文（小红书 / 抖音 / 公众号）。
- 「判定」一列严格按 SKILL.md「每个平台怎么判有没有命中」的判据填，三选一，不要自创风险等级——接口不回等级。
- 某平台走「没拿到结果」分支（有 `error`，或正文字段全缺）时，该行判定填**检测失败**并附 `code`／缺了哪个字段，
  🔴 **不许填「无命中」，也不许编造结果**。
- 「建议」一列由本鸭结合上下文给出——接口不提供建议。
- 全平台均判定为「无命中」时，对照表照常列出，判定一列写「无命中」。

## 2. 全平台安全改写

综合**所有平台**的命中词与建议，给出**一版**改完即可在所有目标平台发布的文案：

【安全改写后的整段文案。要求：覆盖各平台所有**营销语境命中**（只报不改的那档原样保留）；语义通顺、语气与风格不变；
不加 emoji、不重写结构、不加引用或代码块，直接输出。改动处可加粗斜体标出。】
