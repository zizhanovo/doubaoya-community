# 接口契约与参数真相表

**正常出图不用读这份**——`scripts/gen.mjs` 已经把该发的发了、该躲的躲了。
只有这几种时候需要它：用户问「能不能指定尺寸／一次出几张／换模型」、
你怀疑脚本发错了参数、或者要绕过脚本自己发请求。

---

## 接口

```
POST {DOUBAOYA_BASE_URL}/api/skills/gpt-image-gen/invoke
Authorization: Bearer $DOUBAOYA_API_KEY
→ { success, data: { source, taskId, status, images: [{ b64, mime }] } }
```

`prompt` 是**唯一必填**。计费，单价见详情端点的实时点数字段。

---

## 参数三态表（实测日期 2026-08-21）

「这个参数支不支持」这个问法本身会骗人：有的参数**收下了却不起作用**，
有的参数**收下了、送出去了、还照收钱，但产物拿不回来**。前者试一次没损失，
后者试一次白付钱。所以分三态看：

| 参数 | 入参收 | 服务端透传 | 上游生效 | 结论 |
|---|---|---|---|---|
| `prompt` | ✅ | ✅ | ✅ | **唯一真正控制画面的东西** |
| `referenceImage` / `imageUrl` / `images[]` | ✅ | ✅ 最多 3 张 | ✅ | URL / `data:` URI / 裸 base64 都收 |
| `operation` | ✅ | ✅ | ✅ | 不必传，有参考图自动走改图 |
| `modelName` | ✅ | ✅ | ✅ | **可以换模型**，见下方「选哪个模型」。不传就用默认 |
| `quality` | ✅ | ❌ 不再发送 | — | 新上游文档没有这个字段，服务端已停发 |
| `n` | ✅ | ✅ | ✅ **按份数计费** | 🔴 **禁传**，只返还一张 |
| `size` | ✅ | ✅ | ❌ 上游忽略 | 无效，比例只能写进 prompt |
| `background` | ✅ | ❌ 不再发送 | — | 同上，**做不到透明底** |
| `outputFormat` | ✅ | ❌ 不再发送 | — | 输出格式由上游定，实测是 png |

`scripts/gen.mjs` 发 `prompt`、参考图、以及 `--model` 指定时的 `modelName`，其余一概不发。

## 选哪个模型（`--model`）

**不传就用默认，多数请求不必传。** 需要时按这次的诉求选：

| 这次要的是 | 传 | 为什么 |
|---|---|---|
| 快、要多出几版挑 | `gpt-image-2.5-flare`（默认） | 官方称生成延迟约砍半 |
| 改图 / 多轮精修 / 要贴住参考图 | `gpt-image-2.5-sunburst` | 官方称保真度与风格锁定更强 |
| 新版出了问题要退回去 | `gpt-image-2` | 上一代，不推荐日常用 |

⚠️ **两档 2.5 的差异是上游官方说法，我方没有独立验证过**：实测请求这两个 id，
上游回显的 `model` **都是 `gpt-image-2-codex`**，看不出落到了哪个后端。所以别向用户
承诺「换了就一定更保真/更快」，只说「这一档官方定位是 X，可以试」。

传了白名单之外的名字会**在发请求之前**被拒（400，文案里列出可选值），不会白等一趟。

## 仍然做不到的，如实说不能

| 用户可能会要 | 怎么答 |
|---|---|
| 局部重绘 / mask 蒙版 | 无 mask 参数；替代是**整图改图**，在 prompt 里描述只改哪里 |
| 指定精确像素尺寸 | `size` 无效；比例写进 prompt，精确尺寸拿到图之后自己裁 |
| 一次出 N 张候选 | **多次独立调用**，每次单独计费——先把总价告诉用户。🔴 不要用 `n` |
| 透明底 / 换输出格式 / 换模型 | 三个字段服务端不读，传了等于没传 |
| 4 张以上参考图 | 上限 3 张。让用户自己挑，脚本会直接报错而不是替他选 |

---

## `quality`：生效，但默认不要动

受控实测（同一句 prompt，两档交替各 3 张）：

| 档位 | 分辨率 | 文件大小 | 耗时 |
|---|---|---|---|
| `medium`（默认） | 1672×941 | 189 / 184 / 185 KB | 53 / 31 / 47 s |
| `high` | 1672×941 | 213 / 197 / 222 KB | 45 / 32 / 50 s |

- **它确实生效**（与 `size` 不同）：同分辨率下 high 体积一致高出约 13%，三对无重叠。
- **但「high 更好看」没有被证实**——3 张样本不足以支撑这个结论。
- **改档的代价未知**：上游按 quality 怎么计价查不到，我方每次固定收同样的点数。

⇒ 用户明确问起时，如实说这三句，由他决定。**别自己顺手加 `quality:"high"`。**
（`scripts/gen.mjs` 不暴露这个参数，要试得手写请求。）

## 这张表怎么复核

```bash
node scripts/gen.mjs --describe
```

它拉生产实时契约，跟本文件的「入参收」那一列对账：一致打印 ✅ 退出 0，
对不上会列出多了哪些少了哪些并退出 2。**对不上以生产为准，回来把这张表改对。**

⚠️ 端点只答得了「字段在不在」，答不了「传了有没有用」——它的 JSON Schema
不带任何字段描述。后两列只能靠实测。
