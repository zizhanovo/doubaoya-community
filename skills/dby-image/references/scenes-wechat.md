# 公众号四类图的骨架

L3。入口在 [`prompt-ladder.md`](prompt-ladder.md)。只放本平台真正会用到的四类——
不是通用图库（Tattoo、游戏 HUD、等距视图那些对做公众号的人没用）。

用法：挑一个骨架 → 填 `{{}}` → 不满意再按 [`axes.md`](axes.md) 补**一个**维度。

---

## 一、公众号封面

**下游会被裁两次。** 消息列表按 **2.35:1** 裁，转发卡片与主页按 **1:1** 裁——
同一张图两种裁法，所以**关键内容必须落在中央的水平带里**。

```
比例：宽幅横版，16:9 比例
用途：公众号文章封面
构图：主体集中在画面中央的水平带内，上下留出余量；
      {{左侧 / 右侧}}留出空白区域用于叠加标题（只在你确实要叠标题时才写这一行）
{{用户想要的画面内容，原话即可}}
```

上面**只有前三行是这个场景客观躲不掉的**——比例是因为 `size` 无效、
构图是因为会被裁两次。风格、配色、背景一概不在骨架里：
从 [`styles.md`](styles.md) 挑，或从 IP 档案取，或干脆不写。

🔴 **「比例」那一行不能省。** `size` 参数无效，不写比例就会拿到 1254×1254 正方形，
再被按 2.35:1 裁掉上下大半——正好把你精心安排的主体切两刀。

🔴 **上下必须留白**——那两条边会被裁掉。主体顶到边等于被切头切脚。

### 要不要把标题画进图里

**可以，而且中文渲染实测可靠**（见 [`axes.md` 文字](axes.md#文字)，两次难例全对）。
想直接出带标题的封面，在骨架里加一行：

```
文字：主标题「{{标题}}」，粗黑体，{{颜色}}，位于{{位置}}；
      文字必须笔画准确、无错字、无多余字符
```

**但文案没定稿时别这么做**——标题改一个字就要重新出图重新花钱。
定稿了再画进去；没定稿就留白，排版时叠。

## 二、文章内插图

作用是**给读者一个喘气的地方**，不是承载信息。

```
用途：公众号文章内插图
{{这一段在讲的那个东西，用户的原话}}
```

**插图几乎没有客观约束**——不写比例即可（默认约正方形，插图用正方最省事），
也不需要安全区。所以骨架就这么短。

风格从 [`styles.md`](styles.md) 挑；同一篇文章里所有插图**用同一个风格片段**，
否则读者会觉得图是东拼西凑来的。

---

## 三、账号主视觉 / IP 形象

出现频率低但影响大——它会被反复用。

```
比例：正方形
用途：账号主视觉 / IP 形象，会被长期反复使用
构图：主体居中，四周留足边距（会被裁成圆形或小尺寸使用）
{{IP 形象的具体描述 —— 必须来自 IP 档案，见下方红线}}
```

🔴 IP 形象的所有特征（配色、造型、标志性元素）**必须来自 IP 档案**（正文「图里的事实同样不许编造」那条）。
档案里没有就先去 `dby-charter` 把人设立起来。
**这个形象一旦发出去就会被反复复用，编错的成本比一张图大得多。**

## 四、信息图 / 结构示意

用来讲清一个流程或对比。

```
比例：{{宽幅横版 16:9 / 竖版 9:16，看放在哪}}
用途：信息图，向读者解释 {{要讲清的那件事}}
构图：{{横向排列 / 纵向排列 / 网格}}，模块之间留清晰间距
文字：每个模块的标签分别是「{{标签1}}」「{{标签2}}」……，笔画准确、无错字
一张{{流程 / 对比 / 层级}}示意图，共 {{N}} 个模块
```

模块间距与标签是**信息图这个用途的客观要求**（挤在一起就读不出结构）。
风格仍然自己挑——[`styles.md`](styles.md) 的「信息图风格」「几何图形」都合适。

> 写明「用途：信息图」这一句是有用的——OpenAI 指南指出，
> 声明用途能让模型自己切到对的精细度档位。

---

## 五、什么时候不该用生图

诚实的一节。**每次调用都计费**，先判断这张图是不是真的需要生成：

| 情况 | 更好的做法 |
|---|---|
| 需要真实产品照 | 用真照片——生图会编出不存在的产品细节，而那属于「事实不许编造」 |
| 需要真实人物 | 别生成，肖像风险 + 不像 |
| 需要精确数据图表 | 用图表工具，模型画的坐标轴与数值不可信 |
| 只是要一张占位图 | 纯色块就行，别花钱 |
| 文案还没定稿但想连标题一起出 | 先留白，定稿了再出带字版 |
