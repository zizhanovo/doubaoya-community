# 出一张图的提示词阶梯

**这是提示词的入口。绝大多数请求读完这一份就够了，不用再读别的。**

核心原则来自 OpenAI 官方 gpt-image 提示词指南，一句话：
**先跑最小基线，再一次只加一个维度**——别一上来就把所有维度堆满。
堆满的提示词不会更好，只会让你不知道是哪一句起了作用。

---

## L0 · 最小基线：把用户的话原样送出去

**用户说什么就画什么。不要替他加任何限定。**

```
一只鸭子在写稿
```

就这样。**不加风格、不加配色、不加背景、不加「不要文字」。**

> 🔴 **这一条是本文件最容易被违反的一条。**
> 「顺手加个『扁平插画风、纯色背景、不要文字』总没错吧」——错。
> 风格、配色、背景是**审美选择，属于用户不属于你**。你替他选了，
> 出来的图就永远是你的品味，不是他的号的品味。
> 结果就是每张图都干净、正确、且没有任何记忆点。

用户明确说了风格就照他说的；没说而你想给建议，**从 [`styles.md`](styles.md) 里
给他两三个选项让他挑**，别直接定一个。

---

## L1 · 只加这个场景**客观上躲不掉**的约束

L1 加的不是审美，是**事实**：这张图会被怎么裁、哪块会被 UI 遮住、下游要什么比例。

```
比例：宽幅横版，16:9 比例
构图：主体集中在画面中央的水平带内，上下留出余量
一只鸭子在写稿
```

### 什么算「客观约束」

| 算 | 不算 |
|---|---|
| 比例（`size` 无效，只能写 prompt） | 风格 |
| 裁切安全区（会被裁掉的边） | 配色 |
| 平台 UI 遮挡区 | 背景复杂度 |
| 下游用途（信息图 / 海报，影响精细度档） | 「不要文字」这类排除项 |

**排除项不是基线的一部分。** 它是**返工后**才加的补丁——
真出现了伪文字再加「不要文字」，别预防性地全加上。
（常见返工点见 [`axes.md`](axes.md) 各节末尾。）

### 比例速查

| 发布场景 | 比例 | 客观约束 |
|---|---|---|
| 公众号封面 | 宽幅横版 16:9 | 消息列表按 2.35:1 裁、卡片按 1:1 裁 → **上下留余量** |
| 公众号文章插图 | 不写即可（默认约 1:1） | 无 |
| 小红书封面 / 配图 | 竖版 3:4 | 瀑布流卡片小 → 关键信息要大 |
| 抖音 / 视频号 / 快手 封面 | 竖版 | **底部与右侧被播放器 UI 遮挡**；主页网格只露中间 |
| 横屏视频封面 | 宽幅横版 16:9 | 无 |

> `size` 参数完全无效（正文红线六），上表的比例**只能写进提示词**。
> 需要精确像素就拿到图之后自己裁。

[公众号](scenes-wechat.md) · [小红书](scenes-xiaohongshu.md) · [抖音·视频号·快手](scenes-video.md)

## L2 · 只补出问题的那一个维度

出图之后不满意，**先定位不满意在哪一点**，只补那一个维度。

### 症状 → 补哪个维度

| 你看到的问题 | 补这个维度 | 去哪查写法 |
|---|---|---|
| 画面平、没层次、光很假 | **光线** | [`axes.md`](axes.md#光线) |
| 主体位置不对 / 太满 / 没地方放标题 | **构图** | [`axes.md`](axes.md#构图) |
| 颜色和品牌对不上 | **色彩** | [`axes.md`](axes.md#色彩) |
| 图里的字是错的 / 想加标题 | **文字** | [`axes.md`](axes.md#文字) |
| 看起来太"AI"、太干净、不真实 | **质感** | [`axes.md`](axes.md#质感) |
| 要写实照片感但出来像插画 | **相机语言** | [`axes.md`](axes.md#相机语言) |

🔴 **一次只加一个。** 同时加三个维度出来的图如果还是不对，你无法知道是哪一个没起作用，
下一轮只能全推倒重来——而每一轮都要花钱。

⚠️ **别加"质量咒语"。** `8K`、`ultra-detailed`、`masterpiece` 这类词对 gpt-image 帮助很小。
OpenAI 指南明确指出：要写实感，**相机与光线的具体描述比这些形容词可靠得多**。

---

## L3 · 场景骨架（按平台挑一份）

骨架里**只有该场景客观躲不掉的约束**——比例、安全区、下游怎么裁。
**风格、配色、背景一律留空**，从 [`styles.md`](styles.md) 挑，或从用户的 IP 档案取。

| 平台 | 读哪份 | 客观约束是什么 |
|---|---|---|
| 公众号 | [`scenes-wechat.md`](scenes-wechat.md) | 两种裁法（2.35:1 与 1:1）→ 上下留余量 |
| 小红书 | [`scenes-xiaohongshu.md`](scenes-xiaohongshu.md) | 竖版 3:4 瀑布流，卡片小 |
| 抖音 / 视频号 / 快手 | [`scenes-video.md`](scenes-video.md) | 底部与右侧被 UI 吃掉，网格只露中间 |

## 特殊入口：用户给了参考图说「我要这种感觉」

**先反推，再出图。这一步不调接口、不花钱**——用你自己的视觉能力看图，
按下面七项逐条写出来，跟用户确认之后再进 L1。

### 反推七项

1. **主体**：画面里最重要的是什么，什么姿态、什么视角
2. **情境**：它在哪儿，周围有什么
3. **媒介 / 风格**：照片 / 扁平插画 / 水彩 / 3D 渲染 / 线稿 / 水墨
4. **色彩**：主色、辅色、饱和度高低、冷调暖调
5. **构图**：主体在什么位置，留白在哪，是否对称
6. **光线**：光从哪来，硬光柔光，阴影明显与否
7. **质感**：颗粒、噪点、笔触、纸纹

### 两条纪律

- **只描述你真的看见的东西。** 看不出用什么模型画的就别写「Midjourney 风格」——
  那是猜的，对出图没有帮助。
- **反推结果先给用户确认。** 你看到的重点和他想要的重点常常不是一回事，
  确认一次比出错三次便宜。

---

## 出图之后：验收（必做，不花钱）

阶梯到这里还没完。图出来了，**读回它、对着这次的请求核一遍，再交给用户**——
核对表就是从 L0 的「用户原话」和 L1 的「客观约束」两处生成的，
所以这一步是这条阶梯的收口，不是额外加的活。

做法见 [`visual-review.md`](visual-review.md)。零调用、零计费、零自动重出。

---

## 复现与系列：骨架 + 变量

要出一组风格统一的图（一个号的固定视觉语言），把不变的写死、变的留成变量：

```
比例：{{比例}}
主体：{{主体}}
情境：{{情境}}
风格：扁平插画，粗描边，轻微颗粒质感
色彩：主色 {{品牌主色}}，辅色米黄与深棕
构图：主体居中偏左，右侧留白
排除：不要水印、不要边框
```

每张只填两三个变量。**这比每次重写整段提示词稳定得多**，
也是「让一个号的图看起来是同一个号的」最省力的办法。

🔴 `{{品牌主色}}` 这类**必须从 IP 档案取真值**（正文红线四）。
档案里没有就问用户，别自己填一个。
