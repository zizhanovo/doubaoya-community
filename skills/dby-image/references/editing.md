# 改图：只动该动的，别让画面漂

已经有一张图要改它时读这份。入口在 [`prompt-ladder.md`](prompt-ladder.md)。

改图走同一条接口，多带参考图即可（`referenceImage` 单张 / `images` 数组，1–3 张，
公网 URL、`data:` URI、裸 base64 都收）。**不用传 `operation`。**

---

## 核心句式：改什么 + 保留什么

**两句都要有。只说改什么，模型会顺手把别的也改了。**

```
只把背景换成夜晚的书房。
其余全部保持不变：鸭子的造型、姿势、配色、构图位置、光线方向都不要动。
```

OpenAI 指南的原话是 `change only X` + `keep everything else the same`。
中文同理，关键是**「保留」那一句要具体列出来**——泛泛一句「其他不变」效果差很多。

---

## 🔴 多轮改图必须每轮重复保留清单

这是改图最容易踩的坑：**改到第三轮，画面已经悄悄漂成另一个东西了**。

原因是每一轮模型只看到「这一轮要改什么」，而上一轮说过的「保留什么」它不会记住。

```
第 1 轮：只把背景换成夜晚。保留：鸭子造型、姿势、橙色主色、构图。
第 2 轮：只把耳机改成白色。保留：鸭子造型、姿势、橙色主色、构图、夜晚背景。
                                                          ↑ 上一轮的成果也要进保留清单
第 3 轮：只把桌上加一杯咖啡。保留：鸭子造型、姿势、橙色主色、构图、夜晚背景、白色耳机。
```

**保留清单只增不减**——每轮把上一轮改对的东西也加进去。

---

## 🔴 保留清单守得住可数项，**色调和版面看运气**

2026-08-21 同一天两次改图实测，都逐项列了保留清单，结果不一样：

| | 第一次（三只鸭子换围巾色） | 第二次（单只鸭子换围巾色） |
|---|---|---|
| 可数项（数量、顺序） | ✅ 守住 | ✅ 守住 |
| 文字**内容** | ✅ 守住 | ✅ 守住（木牌 "Happy Winter!" 一字不差）|
| 整体色调 | ❌ 去饱和、偏黄 | ✅ 未变 |
| 版面 / 字号 | ❌ 标题变大下移 | ✅ 未变 |

⇒ **可数的离散项（数量、顺序、文字内容）稳定守得住；
色调、饱和度、字号、版面位置这类连续项两次里漂了一次。**

⚠️ 两次样本说明不了「什么时候会漂」，只说明**它会漂**。别据此编原因
（"复杂画面才漂""多主体才漂"都是 n=2 编不出来的）。

⇒ 所以纪律很简单：**改完把新图和原图逐项比一遍，不能只看你改的那一处。**
色调漂移单看新图完全看不出来，只在并排对比时才现形。
[`visual-review.md`](visual-review.md) 在改图场景下的核对表就是它：
**保留清单里的每一项都是一个验收项**。

⇒ 对色调/版面敏感的场景（同系列封面、要跟正文配色对齐的插图），
把它们**写成具体的值**（「背景草地保持饱和的绿色」「标题字号与位置不变」）
比笼统写「场景不变」更有指望——但不保证，还是要比对。

---

## 一次只改一件事

跟出图的阶梯同一个道理：一次改三处，出来不对时你不知道是哪一处的指令没生效。

而且每一轮都要花钱——**三次单改比一次三改再推倒重来便宜**。

---

## 局部重绘做不到，怎么办

当前后端**没有 mask 参数**（见 [`api-contract.md`](api-contract.md)），不能圈定区域重绘。替代方案：

| 用户想要 | 实际怎么做 |
|---|---|
| 只重画左上角那块 | 描述式改图：`只把左上角的云换成太阳，其余全部保持不变` |
| 抠掉某个元素 | `移除画面里的杯子，用背景填补该区域，其余保持不变` |
| 换掉文字 | `只把标题文字改为「新标题」，字体、字号、位置、颜色全部保持不变` |

⚠️ 描述式改图**不保证像素级不变**——它是重新生成一张接近的图，不是在原图上局部修改。
需要像素级保真（比如企业 VI 素材）就别用生图，用图像编辑工具。

---

## 多张参考图：可以，上限 3 张

`--ref` 写几次就是几张。用户要「把 A 图的狗放进 B 图」时两张一起传，
在提示词里说清谁是谁：

```bash
node scripts/gen.mjs "把第一张里的狗，放进第二张的场景，保持狗的毛色与姿势不变" \
  --ref ./dog.png --ref ./scene.jpg
```

🔴 **超过 3 张要告诉用户上限、请他挑**。服务端会静默丢掉多余的，
脚本因此直接报错而不是替他选——替用户挑等于让他不知道哪几张真的起了作用。

> 以前这里写着「只收一张，建议先把多张拼成一张」。那是错的，
> 而且拼图这条绕法本身还会让模型把拼接缝当成画面内容。

## 参考图的三种形态，本机文件直接能用

| 形态 | 写法 |
|---|---|
| 公网 URL | `"https://example.com/ref.png"` |
| `data:` URI | `"data:image/png;base64,iVBOR…"` |
| 裸 base64 | `"iVBOR…"` |

**不需要先上传图床，也不用自己编码。** `scripts/gen.mjs --ref ./本机图.png`
会识别路径、读盘、按字节嗅探类型并转成 `data:` URI。

⚠️ 单张 ≤10MB；只收 png / jpeg / webp，按字节签名认，改扩展名没用。
