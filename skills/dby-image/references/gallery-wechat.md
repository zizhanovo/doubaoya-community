# 公众号主场景的提示词骨架

按需加载。这里只放**本平台真正会用到的几类**——不是通用图库。

外面那些几十个分类的图库（Tattoo、游戏 HUD、等距视图……）对我们没用：
用户来这儿是做公众号的，需要的就下面这几种。每种给一个可以直接填的骨架。

用法：挑一个骨架 → 把 `{{}}` 填掉 → 按 `prompt-craft.md` 的三档决定要不要再压缩。

---

## 一、公众号封面

**下游会被裁。** 微信消息列表按 **2.35:1** 裁，转发卡片与主页按 **1:1** 裁——
同一张图两种裁法，所以**关键内容必须落在中央的水平带里**。

```
比例：宽幅横版，16:9 比例
主体：{{主体，一个就够，别堆}}
情境：{{极简情境或纯色背景}}
风格：{{扁平插画 / 杂志摄影感 / 手绘}}，画面干净
色彩：主色 {{品牌主色}}，背景低饱和
构图：主体集中在画面中央的水平带内，上下留出大片干净背景；
      {{左侧 / 右侧}}留出空白区域用于后期叠加标题
排除：文字、水印、边框、复杂细节
```

🔴 **「比例」那一行不能省。** `size` 参数无效，不写比例就会拿到 1254×1254 正方形，
再被微信按 2.35:1 裁掉上下大半——正好把你精心安排的主体切两刀。

🔴 **上下必须留白**——那两条边会被裁掉。主体顶到边就等于被切头切脚。

⚠️ 不要在图里画标题文字：模型写的中文基本不能看，标题是排版时叠上去的。

---

## 二、文章内插图

正文里的配图，作用是**给读者一个喘气的地方**，不是承载信息。

```
主体：{{这一段在讲的那个东西的具象化}}
风格：扁平插画，线条简洁，与全文其他插图同一套风格
色彩：主色 {{品牌主色}}，整体清淡，不要抢正文
构图：留白充足，主体居中
排除：文字、水印、复杂背景
```

**一篇文章里的所有插图用同一套 `{{变量}}` 模板**（见 `prompt-craft.md` 第二节），
否则读者会觉得图是东拼西凑来的。

---

## 三、账号主视觉 / IP 形象

出现频率低但影响大——它会被反复用。

```
主体：{{IP 形象的具体描述，来自 IP 档案}}
姿态：{{正面站立 / 半身 / 侧面}}，表情{{……}}
风格：{{风格}}，可爱但不幼稚，适合作为长期视觉符号
色彩：主色 {{品牌主色}}，配色不超过三种
构图：主体居中，纯色或透明背景，四周留足边距
排除：文字、复杂场景、多个角色
```

🔴 IP 形象的所有特征（配色、造型、标志性元素）**必须来自 IP 档案**（正文红线四）。
档案里没有就先去 `dby-charter` 把人设立起来，别在这里现编一个形象——
**这个形象一旦发出去就会被反复复用，编错的成本比一张图大得多**。

---

## 四、信息图 / 结构示意

用来讲清一个流程或对比。

```
主体：一张{{流程 / 对比 / 层级}}示意图，共 {{N}} 个模块
风格：扁平几何，粗描边，图标化
色彩：主色 {{品牌主色}}，模块之间用同色系深浅区分
构图：{{横向排列 / 纵向排列 / 网格}}，模块之间留清晰间距
排除：文字标签（文字后期叠加）、装饰性元素
```

⚠️ **信息图里的文字不要交给模型画。** 让它出纯图形骨架，文字排版时叠——
这是模型最不擅长的地方，也是返工率最高的一类。

---

## 五、什么时候不该用生图

诚实的一节：

| 情况 | 更好的做法 |
|---|---|
| 需要真实产品照 | 用真照片，生图会编出不存在的产品细节 |
| 需要真实人物 | 别生成，肖像风险 + 不像 |
| 需要精确数据图表 | 用图表工具，模型画的坐标轴不可信 |
| 只是需要一张占位图 | 纯色块就行，别花钱 |
| 图里必须有准确中文 | 后期叠字，模型写的中文基本不可用 |

**每次调用都计费**（正文有说明），所以先判断一下这张图是不是真的需要生成。
