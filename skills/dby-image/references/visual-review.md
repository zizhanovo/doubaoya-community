# 出图之后：验收这张图

落盘不是终点。**读回这张图，对着这次的请求逐条核一遍，再交给用户。**

这一步**不花钱**——用你自己的视觉能力读本地文件，零调用、零计费。
它是当前唯一一个不换模型、不加成本就能提升交付质量的位置。

---

## 为什么必须做

「调用成功」不等于「拿到了对的图」。

接口返回 200、图也画出来了，但用户点名的咖啡没画、标题多了一个字、比例歪了——
这些**只有看过图的人才知道**。你不看，用户就得自己看；而他看到的时候，钱已经付了。

---

## 核对表从这次的请求生成，不是一份固定清单

🔴 **不要用固定清单。** 固定清单一定会带进用户没要求的项（「背景是否干净」「风格是否统一」），
那是从验收这一侧，把 [`prompt-ladder.md`](prompt-ladder.md) 的 L0 明令禁止的审美预设又塞回来。

**核对表 = 用户原话里的可核项 + 你在 L1 加的客观约束。只有这两个来源。**

| 从哪取 | 取什么 | 例子 |
|---|---|---|
| 用户原话 | **可数元素**：名词 + 数量 | 「桌上有一杯咖啡」→ 咖啡在不在？是一杯吗？ |
| 用户原话 | **点名的图内文字**，逐字 | 「标题写『深夜写稿指南』」→ 六个字一个不错？ |
| 用户原话 | **点名的品牌事实** | 主色是不是 IP 档案里的真值？（正文「图里的事实同样不许编造」那条） |
| 你加的 L1 约束 | 比例、裁切安全区 | 16:9 → 用落盘脚本算出的**实测宽高**判，不目测 |
| 你加的 L1 约束 | 公众号封面的两次裁切 | 跑 `scripts/wechat-crops.mjs`，读 `crop-1x1` 判主体与标题是否完整、读 `thumb360` 判标题是否仍可读——**不对原图目测安全区** |

**用户没说的，不进核对表。** 他没提背景，背景就不是验收项。

**机械能判的交给脚本，眼睛只判脚本判不了的。** 宽高、裁区由脚本算；元素在不在、字对不对由眼睛看。
裁切模拟免费且几秒钟，封面场景必跑；但结论仍按「先把图和核对表给用户」交付，不因为多了脚本就改成自动重出。

---

## 只判可证伪的，不判好不好看

| 算客观项（判） | 不算（不判） |
|---|---|
| 元素在不在、几个 | 好不好看 |
| 文字对不对、错哪个字 | 风格高不高级 |
| 比例数值对不对 | 配色舒不舒服 |
| 品牌色是不是真值 | 构图美不美 |
| 有没有明显结构崩坏（多指、断肢、穿模） | 「有没有高级感」 |

🔴 **审美不进验收结论。** 出图前不替用户选风格，出图后也不替他判风格好坏——
这是同一条纪律的两端。你觉得平淡但客观项全中，就是**通过**，照常交付。

---

## 常见客观缺陷（按实测命中率）

1. **模型自己加的密集小字是乱码笔画** ← 最高频。
   它很爱往画面里加字：书脊、便签、海报、笔记正文。
   **成段的小字多半是乱码；孤立的大字（招牌、标语）通常没问题**
   （见 [`axes.md`](axes.md) 文字一节）。整张扫一遍，别只看你点名的那几个字。
2. **可数元素缺失或数量不对**：说了三只，画了两只。
3. **比例偏离**：没在 prompt 里写比例，拿回 1254×1254 正方形。
4. **点名文字错字或多字**。
5. **结构崩坏**：手指数量、肢体接驳、物体穿模。

## 怎么写判定：一项一行，写出你**看见**的

不要只写「通过 / 不通过」，写出**依据**——否则没人能复核你到底看没看。

```
核对表（据用户原话「画一只戴耳机的鸭子在写稿，桌上有咖啡和摊开的笔记本，
标题写『深夜写稿指南』」+ L1 约束 16:9）：

  ✅ 鸭子           1 只，画面中央
  ✅ 耳机           戴着，深灰色头戴式
  ✅ 咖啡           1 杯，桌面左侧，带热气
  ❌ 摊开的笔记本    用户说「一本」，图里摊开了两本 —— 数量不符
  ✅ 标题文字        「深夜写稿指南」六字逐字准确
  ✅ 比例           实测 1672×941 = 1.777，16:9 达成

  ⚠️ 笔记本数量：用户说「一本摊开的笔记本」，图里摊开了两本。
  ⚠️ 未点名的装饰文字：书脊 4 处、便签 2 处、笔记正文约 12 行，
     其中笔记正文与部分书脊是乱码笔画，放大可见。用户若要发布需注意。
```

## 判完之后：报告，**不要自己重出**

🔴 **零自动重出。** 发现缺陷不等于你可以再花一次钱。

按这三步交付：

1. **把图给用户**（文件路径），连同上面的核对表。
2. **如实说命中了哪几条缺陷**，原样写出来，别概括成「有一些小问题」。
3. **给一条定向修复提示词**，并说明再来一轮要再花一次钱，问他要不要跑。

> 这次的图在这儿：`./doubaoya-image.jpg`
> 核对下来两处对不上：①你说一本笔记本，图里摊开了两本；②书脊和笔记正文有乱码笔画。
> 想修的话，下一轮我会在提示词里补一句「桌上只有一本摊开的笔记本，
> 除标题外画面中不出现任何其他文字」。**再出一轮要再计一次费**，跑吗？

🔴 **一次只修一个维度。** 两处都不对也只针对其中一个改——
同时改两处，出来还不对时你不知道是哪一句没生效，下一轮只能全推倒，而每一轮都花钱
（[`prompt-ladder.md`](prompt-ladder.md) L2 同一条道理）。

🔴 **超时不算缺陷，也不能重试。** 那条走正文「失败之后不要重试」。

## 扫水印：四个角单独看一遍

「有没有文字」这一项**不能只看提示词点名的那几个字**。2026-09-10 实测：一张完全没要求
文字的图，左上角与右上角各带一枚**半透明描边 logo**（无可辨认字符，缩略图上几乎看不见，
放大才认得出），另有画面内海报上几团假标题笔画。上游自动追加的「不包含文字、水印、标志」
**没有拦住它**。

所以核对表里那一条要拆成两步：①提示词点名的文字对不对；②**四个角 + 画面内一切平面
（海报、屏幕、书脊、杯身）单独扫一遍**有没有没被要求的标记。带水印的图交出去，
用户拿去发就是带着别人的标记发。

发现了怎么办：裁掉（若在安全区外）或重出（**要另花一次钱**，由用户决定）。
MUST NOT 自动重出。

## 交付时必须带上的一句

出图成功后 `gen.mjs` 会在 stderr 打一行 `🏷 本内容由人工智能生成`。
**把它转达给用户**——这是 AI 生成内容的法定显式标识，不是可选提示，
也不是打给日志看的。图交出去、标识没跟着走，等于没标。

⚠️ 2026-09-10 之前这条链是断的：服务端把标识挂在信封顶层（正是为了覆盖
「98.6% 调用来自 agent、只在网页写一行等于没标识」这件事），而共享请求层在转发时
把这个字段丢了，全仓没有任何一个包读过它。**挂了没人读 == 没挂。**
