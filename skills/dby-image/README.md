# dby-image · AI 生图与改图（都爆鸭）

一句话要一张图就用它：**文生图**（给一段描述就出图）、**图生图 / 改图**（给一张参考图——本机文件也行——在它基础上改）。
出图后落成本地文件，把路径交给你。

> 怎么用、四条红线、提示词阶梯与验收流程，全部在 [`SKILL.md`](./SKILL.md)。这份 README 只讲装配与边界。

## 前置条件

- **Node ≥ 18**。
- 一条 **`DOUBAOYA_API_KEY`**（doubaoya.com → 登录 → 密钥中心 → 生成）。**生图计费。**
- **必须与 `dby-api` 一起安装**：本包不自己发请求，接口调用经由 `dby-api` 的共享请求层
  （`scripts/lib/locate-dby.mjs` 负责定位它）。找不到会以退出码 3 报 `[MISSING_DBY_API]`。

## 安装

把整个 `dby-image/` 目录放进你的 skills 目录，无需 `npm install`。

## 三个脚本

| 脚本 | 花不花钱 | 做什么 |
|---|---|---|
| `scripts/gen.mjs` | **计费** | 出一张图（文生图 / 改图）。`--describe` 子命令免费，只拉生产实时契约做对账 |
| `scripts/plan-figures.mjs` | 免费 | 给一篇 Markdown 规划「配几张图、放在哪个小节末尾、每张画什么」。纯本机，不接 LLM |
| `scripts/wechat-crops.mjs` | 免费 | 把一张公众号封面按微信实际的三种裁法裁出来，供你核验主体有没有被切掉 |

## 三件最容易踩空的事

- **慢操作**：通常 1–2 分钟，最长 4 分钟。等待期间别打断。
- **失败之后不要重试**。服务端超时会退款，客户端提前放弃**不会**——请求照样跑完、照样扣费，
  重试就是为同一张图付两次钱。脚本因此**没有任何重试逻辑**，这是契约不是疏漏。
- **比例只能写进提示词**。`size` 参数上游完全忽略（换代到 gpt-image-2.5 后复测仍然如此）。
  脚本每次都打印实测宽高，核一眼。

## 最近变更

- **2.0.0**：**请求改走 `dby-api` 的共享请求层**，本包不再自己发 `fetch`（仓内只允许一份请求层）——
  因此从此**必须与 `dby-api` 一起安装**，这是破坏性变更；客户端超时随之由本包内置的 300s
  变为共享层的 450s（服务端出图上限 240s，客户端必须更晚）。
  服务端侧同批换了上游供应商并换代到 **gpt-image-2.5**，据此更新三条实测结论：
  ① 文生图与改图**现在都返回 PNG**（此前文生图是 JPEG——那是因为我方当时显式要求 jpeg，
  该参数已不再发送，格式由上游定）；② 参考图超过 3 张由服务端**明确拒绝**，不再静默丢弃；
  ③ 上游会**改写提示词**并自动追加「不包含文字、水印、标志」——不是我们加的，但用户看到的是结果，
  所以要图内文字时改走后期叠加，别反复重发。补齐 `README.md` / `LICENSE` 与 CLI 引导壳。
- **1.7.4 及更早**：见 `git log`。本包曾于 2026-08-31 随服务端生图能力因 ICP 备案整改整体退役，
  2026-09-09 随该能力恢复而重建。
