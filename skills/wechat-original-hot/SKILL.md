# 公众号原创热门榜（都爆鸭）

本鸭帮你按**行业分类 + 时间区间**捞出微信公众号近期的**原创**热门爆款——专盯原创创作者写出来的爆款，绕开转载、洗稿那一堆，给原创写手看清楚同行在用什么角度、什么切口把原创内容写爆。一个分类下去，终端铺出可点的原创爆文表格，再附一句创作洞察。

> 数据走 **doubaoya.com** 一条线，鉴权用你自己的密钥（环境变量 `DOUBAOYA_API_KEY`，形如 `dyh_…`）。

> 说明：原创榜与 10万+ 爆文榜**接口同源**（都走 `category-time-hot`），区别在**展示层/解读层的侧重**——本技能站在原创创作者视角解读，强调"这是原创写手自己跑出来的爆款"，引导你提炼可复用的原创写法，而不是单纯看阅读量天花板。

## 适用场景

| 场景 | 怎么用 | 拿到什么 |
|------|--------|----------|
| **原创选题灵感** | 拉 `科技数码` 看原创写手近期在写什么、怎么切 | 给自己的原创下一篇找方向 |
| **原创写法拆解** | 横扫某分类原创爆款的标题与开头 | 摸出能复用的原创起标题/切口套路 |

| **原创素材沉淀** | 按分类批量收原创爆文 | 攒一手可参考的原创范本 |

## 工作流（4 步）

### 1. 确认分类与时间区间

**🔴 分类是一张官方闭集，只认赛道全称。** 这里最容易踩的坑不是"哪个赛道没内容"，而是
**名字不在闭集里**：写 `科技`、`财经`、`职场`、`教育` 一律返三张空榜，不是因为这些赛道没数据，
而是因为这四个词根本不是合法赛道名——官方的写法是 `科技数码`、`财富理财`、`职场发展`、
`教育考试`，换上去同一时间区间立刻三张榜满上。上游对闭集外的值**不报错、也不纠正**，只安静
返空，所以"写错名字"和"这个赛道没内容"在返回里长得一模一样。**先对名字，再谈数据。**

官方支持的 22 个赛道（照抄，别缩写、别自造）：

> `人文资讯` `知识百科` `健康养生` `时尚潮流` `美食餐饮` `乐活生活` `旅游出行` `搞笑幽默`
> `情感心理` `体育娱乐` `美容美体` `文摘精选` `民生资讯` `财富理财` `科技数码` `创投商业`
> `汽车交通` `房产楼市` `职场发展` `教育考试` `学术研究` `企业品牌`

**用户说的简称，映射到全称再查**：科技/数码 → `科技数码`，财经/理财/投资 → `财富理财`，
职场 → `职场发展`，教育 → `教育考试`，娱乐/体育 → `体育娱乐`，美妆 → `美容美体`，
房产 → `房产楼市`，创业/商业 → `创投商业`，生活 → `乐活生活`。默认 `科技数码`，一次只拉一个分类。

> `民生资讯` 在官方名单里，但**目前实测拿不到数据**（多个时间窗、多轮重跑都是空）。
> 它不该从名单里删掉——上游哪天补上就能用了——现在别选它就是。

**时间区间的三条硬规矩**（同批实测）：

1. `startDate` 和 `endDate` **都必须给**，少一个直接被打回。脚本不指定时默认
   **结束日 = 今天、开始日 = 今天往前 6 天**（近一周），这个默认是安全的。
2. **别查太老的日期**。官方口径是可回溯 30 天，实测放宽到约 60 天；`startDate` 早于
   「今天往前 60 天」时接口会回一句 **「日期格式错误」——这句话是误导的**，格式没问题，
   是日期超出了保留期。看到它就把开始日往后挪，别去改日期格式。稳妥起见按 30 天用。
3. **数据滞后约两天**。只查今天或昨天必然是空的；要看最新，区间结束日建议取
   **今天往前 2 天**。默认的近一周区间已经包含了出数的那几天，所以照常有数据。

### 2. 调用脚本
```bash
python3 "$SKILL_PATH/scripts/fetch_original_hot.py" --type 科技数码
```
指定区间时**日期按今天现算，别照抄任何写死的日期**（写死的日期迟早滑出 60 天窗口）：
```bash
python3 "$SKILL_PATH/scripts/fetch_original_hot.py" --type 人文资讯 \
  --start "$(date -d '-9 days' +%F 2>/dev/null || date -v-9d +%F)" \
  --end   "$(date -d '-2 days' +%F 2>/dev/null || date -v-2d +%F)"
```
脚本把成功信封里的 `data` 以 JSON 打到 stdout。**每次查询只跑一次脚本**，直接读完整 stdout，别用 `head`/`tail` 预览，也别对同一参数重复调用。

### 3. 渲染原创爆文表格
从 `data.items`（文章数组）里取字段，铺成 Markdown 表格。字段做防御式读取——`title` / `accountName`（账号）/ `readCount`（阅读量）可能缺失，缺了就留空，别报错。标题渲染成**可点链接**（指向文章原文 URL），按阅读量降序排。

| 标题 | 原创账号 | 阅读量 |
|------|----------|--------|
| [示例原创爆文](https://mp.weixin.qq.com/s/xxx) | 某某原创号 | 50,000+ |

### 4. 给一句原创创作洞察
表格之后，用本鸭口吻补一句**原创视角**的洞察：这批原创爆款在用什么切口、哪种写法在跑、原创写手还有什么角度没被写透。落在"怎么把原创内容写爆"上，简短有用，别堆套话。

## 拿钥匙（密钥）

1. 打开 **doubaoya.com**
2. **登录**
3. 进 **密钥中心**
4. **生成密钥**（形如 `dyh_…`）

配置到环境变量（脚本只认这个）：
```bash
export DOUBAOYA_API_KEY="dyh_你的密钥"
```

**铁律：密钥绝不打印、绝不写进文件、绝不回显给用户。** 脚本本身也从不输出密钥。所有请求只发往 **doubaoya.com**。

## 接口与信封

- `POST https://doubaoya.com/api/apis/gongzhonghao/category-time-hot/call`
  （与 10万+ 爆文榜同一接口，原创/10万+ 的区分在展示层解读侧重）
- 鉴权头：`Authorization: Bearer $DOUBAOYA_API_KEY`
- 请求体：`{ "type": "科技数码", "startDate": "YYYY-MM-DD", "endDate": "YYYY-MM-DD" }`
  - `type`：字符串，行业分类，**必须是上面那 22 个官方赛道全称之一**（默认 `科技数码`）
  - `startDate` / `endDate`：`YYYY-MM-DD`，**两个都必填**；开始日不得早于今天往前 60 天
    （官方口径 30 天）；数据滞后约两天
- 返回信封：
  ```json
  {
    "success": true,
    "requestId": "...",
    "data": { "items": [ { "title": "...", "accountName": "...", "readCount": 56789 } ] },
    "error": null
  }
  ```
- **先看 `success`**：为 `true` 才读 `data`；否则读 `error.code` / `error.message`。

## 错误处理

脚本失败时向 stderr 打印 `[error] CODE: message` 并以退出码 1 结束。常见情况：

| HTTP | code | 含义 | 处理 |
|------|------|------|------|
| 401 | `MISSING_API_KEY` / `UNAUTHORIZED` | 没带密钥或密钥无效 | 检查 `DOUBAOYA_API_KEY`，去密钥中心重新生成 |
| 400 | `VALIDATION_ERROR` | 参数不合法（如日期格式错） | 修正分类/日期重试 |
| 402 | `INSUFFICIENT_CREDITS` | 额度不足 | 去 doubaoya.com 充值/续额 |
| 422 | `PROVIDER_NO_RESULT` | 这组入参查不到数据。**多半是开始日超出 60 天保留期**——哪怕它说的是"日期格式错误" | 把开始日往后挪进 60 天内重试，别改日期格式 |
| 502 | `PROVIDER_FAILED` | 上游临时故障（**已自动退款**） | 可安全重试 |

> `502 PROVIDER_FAILED` 会自动退款，重试是安全的，不会重复扣费。

**三张榜都是 0 条**（`success: true` 但没数据）：这不是故障，也**不扣你的点**——响应里会带
一个 `noResult` 标记，点数当场退回。按这个顺序排查：

1. **分类名是不是不在那 22 个里**（最常见，比如写了 `科技` 而不是 `科技数码`）；
2. 区间是不是只覆盖了最近两天（还没出数）；
3. 都对，那就**间隔一会儿原样重试一次**——上游偶发瞬时空值，同一组参数一次空、
   下一次满榜的情况本鸭实测遇到过。**别只凭一次空就断言"这个赛道没数据"。**
