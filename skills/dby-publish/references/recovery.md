# 失败 / 中断后怎么恢复（重跑、残留素材、退点）

> 存草稿失败、中途 Ctrl-C、或不确定草稿箱里到底有没有这一篇时读它。一切以**公众号后台草稿箱**为准。

## 先判断现在处于什么状态

流水线的「保存草稿」是一个子进程一口气做三件事：**正文图预上传 → 封面 thumb 上传 → draft/add 存草稿**。
失败或中断发生在哪一步，残留就到哪一步：

| 你看到的 | 草稿箱里有没有 | 已经发生了什么 |
|---|---|---|
| 「保存草稿子进程失败」 | **没有**（draft/add 没成功） | 正文图/封面可能已上传（见下） |
| 中途 Ctrl-C | **去后台看**——draft/add 请求发出后中断的话可能已存入 | 同上 |
| 「结果待确认」（跑完却没抓到 mediaId） | **去后台看** | 三步可能都已完成 |

🔴 **mediaId 是「已存入草稿箱」的唯一凭据**。没有 mediaId 就不算确认存入，唯一可靠的核对方式是
打开公众号后台 → 草稿箱，按标题找这一篇。

## 重跑幂等吗——不幂等

微信 `draft/add` **每次调用都新建一份草稿**，没有去重。草稿箱里可能已有本篇时直接重跑，
就会出现两份同标题草稿。所以**重跑前先去后台草稿箱确认**：已经有了就不用重跑（想换内容就在后台删旧的再跑）；
没有才重跑。

## 已上传的素材残留怎么处理

- **正文图**：上传到公众号图床，属临时性质、不占素材库配额——失败后残留**不用管**，没被文章引用就没有影响。
- **封面（thumb）**：是**永久素材**，占公众号 5000 个永久素材的配额。失败后重跑会**再传一份**。
  偶尔失败一两次不用管；反复重试或在意配额时，去公众号后台 → 素材库把多余的封面图删掉。

## 哪些情况退点

存草稿**只在成功时扣点**：

- 发布失败（`502 WECHAT_PUBLISH_FAILED` / `WECHAT_COVER_FAILED`）→ 服务端**自动把已扣的点数退回**；
- 参数被前置拦下（`400 VALIDATION_ERROR`）→ 压根不扣；
- 具体扣多少以能力详情端点的实时点数字段为准，别照文档里的数字替用户算钱。

## 从哪一步重来

不确定问题出在哪时，按阶梯重来，每级都比上一级多做一点：

```bash
node scripts/pipeline.mjs --md a.md --title "标题" --render-only   # ① 先确认渲染没问题（免费，不碰公众号）
node scripts/pipeline.mjs --md a.md --title "标题" --dry-run       # ② 彩排：校验账号 + 前置检查 + 扫本地图，不发布
node scripts/pipeline.mjs --md a.md --title "标题"                 # ③ 后台确认无旧草稿后，正式重跑
```

渲染/校验阶段的报错（发布步之前）没有任何副作用，修完直接重跑即可，不用查后台。
