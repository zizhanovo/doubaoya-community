# 写作规范这一份，别只拉不用 + 第 1 步的降级处理

> 用户明确要封面卡 / 导语 / 看点这类「家具」，或第 1 步 `prep` 没能把四样拉齐时读它。

默认拿到的是**常驻部分**：内容该怎么组织 + 平台硬约束。**永远成立、与排版无关**，
第 4 步列提纲、第 5 步写正文、第 7 步自检都照它走。

另外两样**默认只给一行索引，不展开**——因为不知道它们**什么都不会发生**
（文章照常渲染，不会报错也不会破版）。要用时才按段名显式拉：

| 段名 | 是什么 | 什么时候去拉 |
|---|---|---|
| `article-structure` | 封面卡 / 导语 / 看点 / 章节副标题 / 结尾卡的 front matter 字段说明 | **用户明确要这些家具时**（"加个封面卡""配个导语"），拉完照字段写；不写就没有这几块 |
| `theme-variants` | 这套排版给引用块、列表等元素配的形态清单 | 想按呈现效果挑结构时（决定 `**加粗**` / `*…*` 怎么用）；只在**真用这套排版渲染**时成立 |

拉法：`GET /api/wechat/writing-spec?section=article-structure`（`themeName` 参数同样可带）。
🔴 **别猜段名**：写错会直接报 400 并列出可选值，**不会静默给你默认那份**——
这是刻意的，静默回退会让你以为拿到了要的东西。

⚠️ 用户没提家具时**不要主动去拉**：那是可选装饰，默认不展开就是为了不让每次写作
都替它付上下文成本。

🔴 **硬约束那一节不是建议**：违反了会**整篇发布失败**或**内容被静默丢掉**，
而那时你已经写完了。所以它必须在动笔前进上下文，不能等到发布那步才看见。

**拉不到怎么办**（照这个降级，别停）：
- **401** → 密钥无效或缺失，告诉用户去检查，**别跳过**（跳过等于蒙着写）
- **网络错误 / 404** → 打一句「这次没拉到写作规范，按通用 markdown 写」，
  照常往下走，**别重试刷屏、别当故障报给用户**

⚠️ 排版改过之后**重新拉一次**，别把这份内容当长期事实缓存。

**档案是空的怎么办**：`GET /api/ip-profile` 回 `{"profile": null}` = 用户还没建档。
**这时不要带着空档案硬写**——先去 `dby-charter` 用 L0 三问（5 分钟）把定位立起来。
没有靶子写出来的东西「哪句都对但不知道给谁看」，那正是本包要根治的病。

样本少于 3 篇时告诉用户一句实话：「补几篇最像你的旧文，成稿会像得多」，
然后照常往下写——少不是不能写，是别假装写得像。
