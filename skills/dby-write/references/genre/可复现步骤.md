# 体裁手艺 · 可复现步骤（教程 / 实操分享）

> 第 3 步声明「素材形态 = 可复现步骤」时，第 5 步列提纲前读这份。
> 这里是手艺（建议怎么写更好），红线与硬约束在 SKILL.md，本份不重复。

每条建议末尾标证据档：[实证]=真实已发布文章或完整写作系统；[业务]=新闻/写作业务论述（跨语境要迁移）；[经验]=运营者自述、无样本量。

## 这类文章长什么样

- 典型结构是**问题 → 方案 → 步骤 → 踩坑清单 → 结语**。真实范例：《开发将 Markdown 一键发布到微信公众号草稿工具的经验分享》（jimmysong.io，已发布，1209 字），走的正是「问题陈述 → 架构设计 → 发布流程实践 → 开发心得（踩坑）→ 结语」。[实证]
- 标题通常是平实描述，零悬念零颠覆——上面那篇就是。硬套好奇缺口反而让读者觉得伪装悬念（这也是第 3 步常青档不强制缺口的依据）。[实证]
- 「开门见山式」开头对这类是正解而非备选："内容较为严肃、专业性较强的文章"适合开门见山，"对于追求效率的读者来说，具有很强的吸引力"（新闻培训网《12 种公众号爆款文章开头》）。[业务]

## 动笔前必须有什么

- **一套别人照做能跑通的操作**——自己真跑过的步骤、截图、真实报错。缺了它写出来的是理论综述，不是教程。[实证]（判据同第 4 步素材表：B 组缺素材=内容范围不够，标注或缩小范围，别硬撑）
- 学习成本与失败点的一手记录。卡兹克写作系统对方法论分享型的要求："必须坦诚地提到学习成本、时间曲线和常见失败点"，例句："一开始可能会有点笨拙，花的时间比手动做还长"——只画饼是明确的反模式。[实证]

## 开头与结尾

- 开头建议直接从工作流痛点起笔。jimmysong 那篇首句："将 Markdown 文档粘贴进去，渲染后再复制到公众号后台"，紧接着"流程繁琐且重复"——先让有同样痛点的人认出自己，不需要钩子。[实证]
- 结尾通常是心得收束 + 邀请交流（"有问题欢迎留言交流"），不上转化话术。[实证]
- 这类内容的读者行为倾向是**收藏**（"收藏率高的内容往往是干货类、工具类、教程类"，搜索留档摘要级来源，未见样本量）——所以结尾给可执行清单比给金句更贴合读者拿它当参考的用法。[经验]

## 写砸的样子

- **理论堆砌、自己没跑通**：通篇"应该如何"没有一处真实执行痕迹（截图/报错/耗时），读者照做即卡。[经验]
- **教科书腔**："下面我来介绍""首先需要了解"式的知识交代（卡兹克自检 L2/L3 明确排查这类句式）。教程允许交代背景，但建议以"聊着聊着顺手掏出来"的方式给。[实证]
- **只画饼**：只写成功路径，不写失败点与成本，读者跑不通后信任归零。[实证]

## 容易串到哪去

- 串到**并列多项**：把"一套有先后依赖的步骤"写成互不相干的技巧罗列，读者不知道从哪步开始。判据：步骤间有依赖 → 本形态；互不依赖 → 并列多项。
- 串到**带转折的真实经历**：把教程伪装成"我的踩坑故事"却没有真实第一人称锚点。手里只有步骤没有亲历细节时，明确写成操作手册，不伪装成"我的经验"。
