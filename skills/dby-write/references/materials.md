# 第 4 步 · 收素材（七层来源的取法）

> 第 4 步要取某一层、或不确定某层计不计费时读它。SKILL.md 的阶梯表够用就不必读。

## 素材单

每条素材一行，写进正文前先进单；成稿末尾把这张单原样附给用户（标题「素材出处」）。

```
S1 [用户材料]  「……原句或数字……」                         ← 用户本轮贴的文字
S2 [链接]      「……」  https://…  parseDetail 拉取 2026-08-24
S3 [档案/范文] 「……」  范文《标题》
S4 [往期文章]  「……」  《标题》 https://mp.weixin.qq.com/s/…
S5 [ima]       「……」  知识库「名称」/ 条目标题
S6 [wiki]      「……」  $DBY_WIKI_DIR/路径.md
S7 [素材卡]    「……」  素材卡 #ki_xxx（存卡 2026-08-25，本轮已向用户核实仍作数）
S8 [取数]      「……」  api.gzh.hotArticle 2026-08-24（计费）
S9 [查证]      核实 S3 的数字仍成立  来源 URL
```

没进单的细节不许进正文；进了单的，正文里那句话要能指回它的编号。

## 1. 用户当轮给的材料（免费）

贴的文字、数字、截图里的字：原样入单，出处写「用户材料」。
链接：先问自己宿主能不能直接抓正文（WebFetch 之类）——能就用宿主的，免费；
抓不到（公众号 / 小红书 / 抖音这类反爬页）再走 `dby-api` 的 `tool.content.parseDetail`：

```bash
node <dby-api>/scripts/doubaoya.mjs describe tool.content.parseDetail   # 先看入参与价格
node <dby-api>/scripts/doubaoya.mjs invoke tool.content.parseDetail '{"url":"<链接>"}'
```

🔴 `parseDetail` **计费**（describe 显示 `unitPrice: 4`），不是免费路由；调用前照 `dby-api` 的计费规矩告诉用户。
返回的是归一化字段（标题 / 作者 / 点赞 / 分享…），不保证带全文——拿不到正文就把链接留在素材单里、正文留占位，别自己补一段「大意」。

## 2. 号档案 + 范文（免费，第 1 步已拉到）

`prep --json` 的 `charter` / `persona` / `products` / `samples[].content` 就是这一层，**不再取**。
出处写「档案·字段名」或「范文《标题》」。范文里的案例可以用，因为它就是用户自己写的。

## 3. 自己的往期文章（免费）

```bash
node scripts/write.mjs articles                 # 最近 20 篇：序号 标题 日期 链接
node scripts/write.mjs articles --q 关键词       # 标题或正文命中的
node scripts/write.mjs articles --id 3           # 第 3 篇正文（去标签纯文本）
```

走 `GET /api/ip-profile/wechat-history`（授权公众号最近 20 篇，免费）。
🔴 **不要自己去调 `GET /api/articles`**——那条只认登录态，拿密钥调必回 `UNAUTHORIZED`。
没绑公众号时脚本退出码 3，这层跳过，别停下来问。出处写「往期文章《标题》+ 链接」。

## 4. 素材库（免费，prep 已带索引）

用户以前讲过、确认存下的经历蒸馏卡。`prep` 的「素材库」节就是索引（proof 一行一条）；
全文按需取：

```bash
node scripts/write.mjs material list          # 索引：proof + 适用形态 + id
node scripts/write.mjs material get <id>      # 单卡全文（时间/地点/后果/出处）
```

🔴 **卡是存卡那一刻的快照** —— 用之前把卡面念给用户核实「这卡还作数吗」，
数字、时间、结局都可能已经变了。核实过的卡进素材单，出处写「素材卡 #id」，
红线一照常约束（卡不是来源豁免通道）。

### 存卡（只在用户确认后）

交付后用户口述了新经历、或用户主动说「记住这件事」时，先蒸馏再展示卡面，确认后：

```bash
node scripts/write.mjs material save '{"proof":"…","event":{"time":"…","place":"…","outcome":"…"},"evidence":"亲历","forms":["带转折的真实经历"]}'
```

蒸馏三问（缺一样就不入库，如实告诉用户缺哪样）：
- **proof**：这件事**证明了什么**？（一句话 ≤80 字——它是检索键，也是这张卡的主键）
- **三要素**：什么时候 / 在哪或在做什么 / 结果怎么样（各 ≤60 字）
- **出处**：怎么核对？（亲历 / 链接 / 聊天记录）

🔴 **不存原文**：服务端拒收长文（content 必须为空）。囤积对写作是负资产——
低质语料全塞比不塞还差，素材库的价值在归因过的浓缩。
删除：`material del <id>`（硬删，索引即时不含）。
📌 素材卡只用于给你自己的写作供上下文，**绝不用于任何模型训练或跨用户分析**（平台承诺，隐私政策同句）。

## 5. 用户自己的知识库（可选，配了才用，没配不追问）

⚠️ **「没配不追问」只对 B 组成立。** 第 3 步声明素材形态是 **A 组**
（带转折的真实经历 / 被访者原话）时，七层取完仍拿不到锚点 **必须停下来问用户**，
不能因为「知识库没配」就跳过 —— A 组缺的不是资料，是那件事本身。
处置阶梯见下方「锚点收不到时」。

### 5a. 腾讯 ima 知识库

官方给的是一个 **skill 包**（ima.qq.com/agent-interface 的「IMA Skills 官方接入包」，名为 `ima-skills`，含 `notes/` 与 `knowledge-base/` 两个子模块），凭证是 `IMA_OPENAPI_CLIENTID` + `IMA_OPENAPI_APIKEY`（或 `~/.config/ima/client_id` / `api_key`）。

判定：宿主的 skill 列表里有 `ima-skills`，**或** `IMA_OPENAPI_APIKEY` 与 `IMA_OPENAPI_CLIENTID` 都非空且 `~/.claude/skills/ima-skills/SKILL.md` 存在 → 加载它，按它的 `knowledge-base` 子模块做「搜索知识库」；两者都没有 → 跳过，不问用户要不要装。
检索到的条目出处写「ima 知识库「库名」/ 条目标题」。
🔴 本包不写 ima 的 HTTP 调用方式——接口形状由那个 skill 维护；它在就用它，不在就没有这一层。
调研留存：`docs/research/dby-write/ima-official-skill.md`、`ima-mcp-csdn.md`。

### 5b. 本地 wiki / 笔记目录（Obsidian、llm-wiki 之类 md 目录）

约定环境变量 `DBY_WIKI_DIR`。没设就跳过。

```bash
rg -il "<关键词>" "$DBY_WIKI_DIR" --glob '*.md'    # 命中的文件，再 Read 需要的那几篇
```

出处写「wiki 文件相对路径」。笔记里转述的第三方数据仍要在第 7 层核实一次。

## 6. 平台取数（计费）

只在用户点名、或前五层凑不出这篇要的事实时用，用前照 `dby-api` 的计费规矩说明：

- 同题材爆文 `api.gzh.hotArticle` → 取法与「爆文是素材不是模板」的约束见 `references/hot-samples.md`
- 热点 `api.trend.hotSpotKeyword` → 必须收窄时间窗口，见 `dby-api` 的 gotchas

出处写「operationKey + 日期（计费）」。别人文章里的案例与数字属于别人：可以引用并标出处，不许改写成自己的经历。

## 7. 联网查证（免费，只核不引）

用宿主自带的搜索 / 抓取工具，**只用来核实前五层已经拿到的事实**（数字还成不成立、产品还叫不叫这个名）。
搜到的新数据不许直接进正文——它没有经过用户，进单只能标「待用户确认」，正文留占位。

## 锚点收不到时（SKILL.md 第 4 步的处置阶梯）

七层取完仍没有一件**真发生过、有明确时间或后果**的事 —— **停下，不许开始写正文**。
按这个优先级走：

**① 先查素材库。**免费、零打扰：`material list` 扫 proof 索引，像是这篇能用的就
`material get` 取全文，**念给用户核实「这卡还作数吗」**，核实过才算锚点到手。
（第 4 层已查过就别重复调，直接进②。）

**② 向用户要。** 问法必须是他能直接回答的具体问题，不是「请补充素材」：

> 这篇要写你自己的经历，但我手里没有能落地的细节。
> 麻烦你用三句话说清楚：**什么时候**、**在哪/在做什么**、**结果怎么样**。
> （例：上周三改配置，把 Base URL 填成了带 /v1 的，一直 404，翻了半小时才发现。）

**③ 用户给不出 → 改成不需要第一人称的写法。** 明确告诉他交付物会变成什么：
不再是「我的经历」，而是操作手册 / 方法整理 / 对一件公开事件的判断。**别偷偷改，要说。**

**④ 素材与原定方向不符 → 改方向，服从素材**，别把素材硬掰回预设主题。

🔴 **「先写一个大家都可能遇到的场景过渡一下」不在选项里。**
业内遇到素材缺口的标准反应只有「问当事人 / 问周边人 / 调整方向」，
（查素材库=问过去的当事人）没有别的。硬填出来的通用场景为什么必然露馅，见红线一第二款。


## 红线一的两类实证：编造具体值 / 不可核对的通用场景

> 「报告写到一半，要分析一份表格……刚准备继续，发现内置积分不够了」

这句话**没有编造任何具体事实**：没有日期、没有数字、没有品牌承诺。
它恰恰是靠**把具体性全部抽掉**，绕过了「不许编造具体事实」这层理解 ——
所以红线一的判据不是枚举「哪几类不许编」，而是「每一样具体东西都要能指出来源」。而它正是 AI 腔最重的来源。

依据：三个真实翻车案例（编造的高考分数、杜撰的采访现场、被当事人否认的转述）
**读起来都很像真的**，全部因细节经不起核对而失败。
「读起来自然」区分不了真实与高仿，只有「能不能指出来源」可以。

另一类实证：曾把品牌主色编成 `#15785A`，真值是 `#FF8708`（全仓 21 处）。

📌 这与第 3 步的素材形态、`craft.md` 的「首句钩住」是**同一条判据**：
**可核对 vs 对谁都成立。** 三处别各自漂移。
