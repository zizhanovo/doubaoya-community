# 模式 B：复盘一篇（四步）

> 用户说「这篇为什么没人看 / 复盘一下 / 数据怎么样 / 上次那篇效果」时读它。写一篇（模式 A）不需要读。

```bash
node "$W" review     # $W = write.mjs 安装全路径，见 SKILL.md 第 1 步
```

它替你做了**算术**那三步：取数 → 按**这个号自己的历史中位数**算两轴基准 → 归四象限。
判断仍归你：**只给一处修复动作**。

### 🔴 脚本替你守住的三条，你仍要照着说

1. **每次输出都要写明用的是哪一档指标。** 脚本默认打**代理档**（横轴阅读数、纵轴点赞÷阅读）
   并把差别打在最前面。🔴 **代理档绝不能被说成「打开率 × 分享率」**——
   真实的打开率与分享率在微信数据统计里、需额外授权，这个接口拿不到。
   阅读数受推荐流影响、不等于粉丝打开；点赞率反映共鸣，跟分享率相关但不等价。
   > 记得给升级路径：让用户去公众号后台「内容分析 → 单篇文章」拿真值贴回来，按真值档重跑。
   > 真值档口径：**打开率 = 公众号会话阅读人数 ÷ 送达人数**（只算订阅者从会话点开，朋友圈等来源不计）；
   > **分享率 = 分享次数 ÷ 阅读人数**。后台单篇页直接给这几个数，让用户抄这两组，别抄总阅读。
   > 后台「数据报告」另有三项官方指标，能拿到就一并带上：**100% 完读占比**（低 = 中段拖沓）、
   > **5% 处跳出率**（高 = 开头 150 字没兑现标题）、**引导关注人数**。网传的「完读 35% / 打开 40%」类权重百分比无出处，官方从未公布，不采。
2. **基准只能是这个号自己的历史中位数。** 🔴 两条约束，缺一条都会错得很自信：

   **① 绝不用行业平均值**——那些数字全是二手孤证、且跨了平台的算法时代，拿来当基准会得到
   系统性错误的判定。脚本结构上做不到引入外部常数（把全部阅读数放大十倍，分类结果不变，
   `selfcheck` 钉着这条）。

   **② 用中位数，不用算术均值**（2026-08-24 修正，此前是均值）。公众号阅读数是典型长尾：
   9 篇 500 阅读 + 1 篇 5 万，均值 5450、中位数 500 ⇒ **用均值时那 9 篇全部落进「低量」**，
   而「低·低」的处方是「选题就错了，回到选题层重做」—— 等于**一篇爆款让这个号其余所有文章
   都被判成选题错误**，越活跃的号被坑得越狠。
   ⚠️ 上面那条「放大十倍分类不变」**抓不到这个**（等比放大时均值与中位数一起放大），
   所以另有一条长尾偏斜断言专门钉它：10 篇里至多 1 篇可判「低量」。
3. **样本少于 5 篇时基准不可靠。** 脚本会打「本次仅供参考」，
   你**不许照常给结论**，得把这句话带给用户。

### 四象限与处方

四象限法出自木木老贼《如何提高公众号的打开率、分享率？》（2018），原文用**历史平均数**作基准；本包改用中位数，理由见上。

| 象限 | 说明 | 该修哪一处 |
|---|---|---|
| 高 · 高 | 成功范式 | 沉淀成模板，复制它 |
| **低量 · 高共鸣** | 内容被认可，败在标题上 | **只修标题，正文一个字别动** |
| 高量 · 低共鸣 | 标题成功，内容没给到社交货币 | 修正文，标题别动 |
| 低 · 低 | 选题就错了 | 回到选题层重做 |

🔴 **只给一处修复动作。** 不要对同一篇同时给多个方向的建议——
四象限的全部价值就在于把修改面收敛到一处。

### 「推荐阅读」与「关注转化」分开评

推荐流 / 看一看带来的阅读**涨粉率低、读者一半不在圈层**（36 氪：小号推荐流量占 45.9%、大号 2.2%；新榜采访多位创作者同向）。
所以阅读量高不等于这篇涨了粉：有「引导关注人数」就用它评涨粉，只有阅读数时如实说「这是推荐阅读，不代表关注转化」。
分享多但关注少 = 引导缺失（文前一行定位 + 文末关注卡，见 `craft.md`），不是选题错。
删旧文、互关、关闭群发通知、自己刷新、用助推券对推荐**无影响**（微信公开课官方口径），复盘时别把它们当变量。

### 找出仍在涨阅读的复利资产（四象限之外的一行）

四象限判的是单篇当期表现；另有一类文章发布后阅读还在涨（搜一搜、看一看、文末推荐、话题标签带来的长尾），
它们是这个号的**复利资产**：优先内链、到期（6–12 个月）优先更新，处方与四象限分开给，别把它们判成「高·高沉淀模板」了事。
识别办法按手里有什么：有两次以上复盘记录 → 比较同一篇的阅读数增量；只有一次快照 → 让用户从后台
「内容分析 → 单篇 → 阅读来源」抄搜一搜 / 看一看占比，占比明显高的就是；两样都没有 → 如实说「这次判不出哪篇还在涨」，
不要拿阅读数绝对值硬猜。（woshipm · `docs/research/writing-thinking/monetize/12`；Ahrefs · monetize/05）

### 复盘结束：提议存一张反馈卡（用户确认才写）

服务端每周会自动记一行数据快照（最佳文 + 关键词，`review_conclusion`，prep 索引里叫「复盘快照」）。
**归因判断**则是你的活：结论展示完，若这次复盘能提炼出一条「写法特征 → 象限」的归因，
把卡面给用户看，确认后存：

```bash
node "$W" material save '{"proof":"教程体+无缺口标题，这个号照样高打开","kind":"feedback","event":{"time":"2026-08 复盘","place":"公众号后台","outcome":"打开率居自身历史上四分位"},"evidence":"链接:<文章url>","forms":["可复现步骤"],"label":{"pattern":"教程体·标题无缺口","quadrant":"高打开高互动"},"articleId":"<文章id>"}'
```

下一轮写作 `prep` 的素材库索引就带着它——第 2/3 步选题定目标时自然在场。三条措辞纪律：
- 🔴 这是**相关不是因果**：样本是一篇文章，写法特征与结果同时出现不等于前者导致后者
- 🔴 引用时说「**这个号自己的历史归因**」，不说成普适规律
- 🔴 反馈卡不足 5 张时带「样本少、仅供参考」（与四象限基准的样本纪律同一条）
喂标签，不喂原文——卡里只放归因，不放文章内容。同一篇重跑复盘不会重复写入（按文章幂等）。

🔴 **归因聚合时排除 `label.quadrant` 以「未验证」开头的卡**（如 `未验证·作者自评`，稿件面星标写入的那类）：
这类卡是作者在审稿页点星标时的主观自评，没有真实阅读 / 点赞数据撑腰，混进「写法特征 → 象限」的统计
会污染这个号自己的真实归因（它凭什么落在这一象限，答案是「作者觉得」不是数据）。数「这个号在哪个象限
出现最多」「哪种写法特征常伴高共鸣」这类结论时，先过滤掉这批卡，只用有真实指标支撑的 `quadrant`。

### 用户点名的文章不在绑定号里

`review` 只拉**当前绑定公众号**的已发文章。用户点名的那篇不在清单里时分两种：
发在别的号 → 让用户去 doubaoya 绑那个号再跑；那篇没群发过 → 无数据，如实说，别拿别的文章顶替。

### 阅读数全为空怎么办

`readCount` 全是 `null`（公开数据查不到）时，**如实说拿不到指标**，
不要用点赞数单独硬凑一个象限判定出来。
