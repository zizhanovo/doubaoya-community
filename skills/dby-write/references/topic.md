# 第 2 步 · 选题的两道筛

> 用户已经说了写什么时**不用读这份** —— 直接用他给的题。

**用户已经说了写什么 → 直接用，不要再问，也不要再调接口。**

用户没说时才取候选：

```bash
node "$W" topics [赛道]      # 不传赛道则用档案里的；$W = write.mjs 安装全路径，见 SKILL.md 第 1 步
```

候选用号章程筛：够不够热、人设的真实视角接不接得住；**接不住的再热也放掉**。

**有用性门槛**（用户给的题也过）：**对吗 × 重要吗（多少人 × 多在乎）× 读者不知道吗 × 能说多硬**，
各打 0–3 分相乘，任一为 0 就换题；新颖点去**流行但错误的常识旁边**找。

→ 用户说「参考同题材的爆款」时读 `references/hot-samples.md`（计费）。

## 复利文配额与常青回看（目标 = 常青时的两条动作）

- **每月至少一篇复利文**：读者反复问的问题，给权威、完整、可执行的答案，标题含「怎么做 / 是什么 / 为什么 / 最好的」。
  候选里一篇都没有时补一个进候选，标注「复利」。定题先判**语义核心 3 年内变不变**：会变归热点文，不变才归常青文，
  只对常青文做搜一搜关键词。（HubSpot · `docs/research/writing-thinking/monetize/04`；Ahrefs · monetize/05）
- **常青文每 6–12 个月回看一次**：更新数据、补案例、改标题，放着不动会被更新者挤下去。
  用户没说写什么时，先用 `node "$W" articles` 扫一眼有没有到期的常青文——**更新旧文优先于新开题**，
  给用户的候选里把它列在第一位并写明「这是更新不是新写」。（Ahrefs · monetize/05；woshipm · monetize/12）

## 素材库里的反馈卡（有就看一眼）

`prep` 索引里 `[反馈]` 开头的卡是这个号自己的复盘归因（写法特征 → 象限）。
选题与定目标时可作参考，但措辞要稳：那是**这个号自己的历史归因，不是普适规律**，
且多为单篇样本（相关非因果）；不足 5 张时带「仅供参考」。详见 `review-mode.md`。
