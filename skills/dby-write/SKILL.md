# 公众号文章写作主干 · dby-write

> 🔀 「帮我写篇文章 / 写个初稿 / 按我的风格写」= **写一篇**（模式 A）；
> 「这篇为什么没人看 / 复盘 / 数据怎么样」= **复盘一篇**（`references/review-mode.md`）。
> B 的结论会被存下来，A 的第 1 步会读到它。
>
> ⚠️ 拿着**已写好的文案**要改成某平台风格 → `dby-rewrite`；拿着**已写好的正文**只要排版或存草稿
> → `dby-publish`。本包管「从没有到有」这一段。

---

## 🔴 四条红线（任何终态下都不许跳过）

### 红线一：事实类内容不许生成

**细节、案例、具体数字、品牌与产品事实（名称 / 颜色 / 价格 / 功能 / 承诺）
只许来自三个地方**：

1. 用户的 IP 档案（号章程 / 创作 DNA / 个人产品）
2. 用户的范文样本
3. 一次真实的取数调用结果

三个地方都取不到时，**留一个显式占位并告诉用户需要补什么**，
绝不用一个看起来合理的值填上去。（实证：曾把品牌主色编成 `#15785A`，真值是 `#FF8708`。）

占位就长这样，别美化它：

```
【待补：本鸭的品牌主色 —— 档案里没有这个字段，请你给一个真值】
```

### 红线二：标题没定，不往下走

出候选 → 用户选定 → 才继续。用户没选就停在这儿等，不许自己挑一个继续写。

### 红线三：标题必须与正文匹配

标题承诺了什么，正文就得兑现什么。标题写「5 个方法」正文只有 3 个 → 自检不通过，改一侧再交付。
「高点击低分享」会被平台判为低质并降权。

### 红线四：成稿必须先给用户过目

**用户没看过正文之前，绝不进入写进他公众号后台的那一步**——
哪怕他一开始就说了「写完直接推草稿箱」。写进用户自己的号是 `write_external`；平台限流
AI 直出内容，成品链路里必须有一处真实的人类决策。

## 模式 A：写一篇（七步主干）

**这七步内部一口气走完，不要逐步征求同意。** 全程只有两个地方停：第 3 步让用户选标题、
第 7 步之后问终态，其余五步直接做。**边界必问，边界内不问。**

⚠️ 先读 `dby-gateway/references/protocol.md` 再发请求。

### 第 1 步 · 读档案 + 拉写作规范（必须早于任何生成动作）

```bash
node scripts/write.mjs prep          # 四样一次拉齐；--json 出机器可读版
```

四样一次拿到手：**号章程**（该做什么）、**创作 DNA**（什么味）、**范文样本**（真实细节的唯一
合法来源）、**写作规范**（平台硬约束）。失败已由脚本按降级阶梯处理：
401 直接红、**档案为空直接拦下**（先去 `dby-charter` 立定位）、规范拉不到照常往下走、范文少于 3 篇提醒。

#### 写作规范这一份，别只拉不用

默认拿到的是**常驻部分**：内容该怎么组织 + 平台硬约束。
第 4 步列提纲、第 5 步写正文、第 7 步自检都照它走。
🔴 **硬约束那一节不是建议**：违反了会**整篇发布失败**或**内容被静默丢掉**，
所以它必须在动笔前进上下文。

→ 用户明确要**封面卡 / 导语 / 看点**这类「家具」，或 `prep` 没把四样拉齐时读
`references/writing-spec.md`，不需要就别读。

### 第 2 步 · 确定选题

**用户已经说了写什么 → 直接用，不要再问，也不要再调接口。**

用户没说时才取候选：

```bash
node scripts/write.mjs topics [赛道]      # 不传赛道则用档案里的
```

它内部已经并进了**你自己表现最好那篇文章的信号**。拿到候选后用第 1 步的号章程筛一遍：
判据两条一起看——够不够热、这个人设的真实视角接不接得住；**接不住的哪怕再热也放掉**。

→ 用户说「参考同题材的爆款」时读 `references/hot-samples.md`（多取一样：同主题爆文样本，
走 `dby-api` 的 `api.gzh.hotArticle`，计费），不需要就别读。

### 第 3 步 · 定标题（🔴 唯一的中途停顿点）

出 **5 个候选**，每个都要过下面五项自检；然后**停下来让用户选一个**
（用户也可以自己给一个）。

| 检查项 | 通过标准 |
|---|---|
| 字数 | 15–28 字（超 30 手机端被截断） |
| 关键词前置 | 核心词在前 15 字内 |
| 情绪触发 | 至少一个情绪词 |
| 受众匹配 | 目标读者一眼认出「这是写给我的」 |
| 搜索适配 | 含读者真会去搜的关键词 |

→ 想挑一种标题写法（关键词吸睛 / 冲突反差 / 提问 / 悬念 / 场景 / 经验分享 / 强调）见 `references/craft.md`。

⚠️ 写标题时**想一遍读者转发到朋友圈的场景**：会不会违背他的人设、给他心理负担？
让人不好意思转发的标题直接砍掉。

### 第 4 步 · 列提纲

→ 四种可选结构（问题-方案-行动 / 故事-观点-延伸 / 热点-解读-预判 / 清单-深度-总结）
见 `references/craft.md`，**选一种，别混着来**。

**小标题 = 论点，每个小标题下先列关键词 = 论据。** 提纲这一步只写到这个粒度就够。

**定形状就在这一步**：对照第 1 步写作规范里「什么内容写成什么结构」那一节——
哪几段该是有序列表（有先后的步骤）、哪几段该是表格
（两个以上对象在同几个维度上对比）、哪句该单独成引用块（一句判断/结论）。

### 第 5 步 · 写正文

**按「块」写，一个一级小标题算一块。** 顺序：先导语 → 再正文 → 最后结尾。

→ 开头 / 结尾 / 衔接三条手法与 `**加粗**` `*…*` 两档重点标记的确切用法见 `references/craft.md`。
**内容不够时不要扩写，去写细节**——但细节必须从范文样本或取数结果里取（红线一）。

🔴 **平台硬约束边写边守**，具体哪几条以第 1 步拉到的规范为准，**别照本文档或记忆里的旧清单写**。

🔴 **口吻按这个号自己的声音写，不是按你的**。第 1 步 `prep` 的输出里有两样东西，
**动笔之前就要用上**：

- `voiceSystemPrompt` —— 这个号蒸出来的口吻基准。**当写作时的口吻设定**，整段读进去再动笔。
- `taboos` —— 硬性禁用词，**一个都不准出现在成稿里**（作者不用的词，以及「赋能」「说白了」
  这类一眼 AI 味的腔调）。写完自己扫一遍。

两样都为空时 `prep` 会警告：**照常往下写**，交付时告诉用户成稿是通用口吻，
想写得像本人去 `dby-charter` 用范文蒸一份。**别因为没有 DNA 就停下来问**。

**结尾的行动号召从档案里取**（`ctaScript` / `credibility`，两样都空就按红线一留占位，
**绝不自己编一个背书**）——取法见 `references/craft.md`。

### 第 6 步 · 写摘要与留言

**摘要**按「备用标题」写（别写成正文缩写），**留言**是作者给自己文章的第一条留言。
→ 怎么写见 `references/craft.md`。

### 第 7 步 · 成稿自检

四件事，一件都不能少：

1. **违禁词** → 走 `dby-banned-words`（红线，任何终态都要跑）
2. **标题与正文匹配**（红线三）
3. **事实来源核对**：正文里每个具体细节 / 案例 / 数字 / 品牌事实，逐个回答「它从哪儿来」，
   答不上来的改成占位（红线一）
4. **平台硬约束逐条对**：拿第 1 步那份写作规范的「硬约束」小节对着成稿过一遍。
   第 1 步没拉到规范时如实说「这次没能按硬约束核一遍」，**别假装核过了**。

自检过了 → 把成稿**交给用户看**（红线四），然后问终态。

---

## 交棒：问终态，再决定走多远

成稿之后**必须问**，不许推断；终态门以 `dby-api/references/wechat-routing.json` 为准：

> 这篇你想要到哪一步？
> ① 就要这份成稿，我自己发 ② 要排版好的公众号 HTML ③ 存进我自己的公众号草稿箱

① 到此为止，不跑 `dby-publish`；② 交棒 `dby-publish`，用 `node scripts/pipeline.mjs --md 稿子.md --title "标题" --render-only`
（🔴 **不需要绑公众号**，有密钥就行、渲染免费——别为了看排版让用户先去绑号）；
③ 交棒 `dby-publish` 跑完整流水线（**那一步才需要已绑号**）。
换平台再发一版 → `dby-rewrite`；调排版样式 → `dby-theme`。

回执随交付写，四行：**查阅 / 执行 / 质检 / 跳过**。看见了但按终态判断这轮不该走的那一步，
**写进「跳过」并说明原因**。

## 模式 B：复盘一篇

→ 用户说「这篇为什么没人看 / 复盘 / 数据怎么样 / 上次那篇效果」时读 `references/review-mode.md`
（`write.mjs review` → 按**这个号自己的历史中位数**算两轴基准 → 归四象限 → **只给一处修复动作**），
不需要就别读。🔴 三条不许简化掉：**写明用的是哪一档指标**（代理档绝不能说成「打开率 × 分享率」）、
**基准只能是这个号自己的历史中位数**、**样本少于 5 篇要把「仅供参考」带给用户**。

---

## API 契约

→ 要绕开 `scripts/write.mjs` 自己发请求时读 `references/api-contract.md`，不需要就别读。
档案读取 / 选题卡 / 复盘取数**全部免费**；档案的**写入**不在本包，走 `dby-charter`。

## 下一步

| 拿到什么 | 下一步 |
|---|---|
| 成稿，要排版好的 HTML 或要进草稿箱 | `dby-publish`（渲染 / 配图 / 封面 / 存草稿） |
| 成稿，还想发别的平台 | `dby-rewrite`（七平台调性，纯本地不计费） |
| 成稿，嫌排版样式不对 | `dby-theme`（改默认排版主题） |
| 自检时要查违禁词 | `dby-banned-words`（三平台口径一次比对） |
| 第 1 步发现档案是空的 | `dby-charter`（先立定位，别带着空档案硬写） |
| 用户不确定接下来该干嘛 | `dby`（公众号飞轮的总导航） |
