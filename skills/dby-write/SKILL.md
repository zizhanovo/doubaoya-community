# 公众号文章写作主干 · dby-write

> 🔀 「写篇文章 / 写个初稿」= **写一篇**（模式 A）；「为什么没人看 / 复盘」= **复盘一篇**（模式 B）。
>
> ⚠️ **已写好的文案**要改平台风格 → `dby-rewrite`；**已写好的正文**只要排版 / 存草稿 → `dby-publish`。

---

## 🔴 四条红线（任何终态下都不许跳过）

### 红线一：写进正文的每一样具体东西，都要能指出来源

**细节、案例、数字、品牌与产品事实、以及第一人称场景 —— 每一样都必须能指回素材单里的一条**
（第 4 步收的）。指不回的，**留显式占位并告诉用户要补什么**，绝不用一个看起来合理的值填上去。

🔴 **场景最容易漏**：它不含数字也不含品牌名，看着没什么可核对的就被跳过。判据一视同仁 ——
这段场景里**有没有任何一个**能指出来源的东西（时间 / 数字 / 引语 / 可查证的对象）？
一个都没有 ⇒ 违反本条，改占位或回第 4 步走锚点阶梯。
⚠️ **不误伤**：细节都能指回素材单的场景，不因「读起来像模板」被拦 —— 判的是能不能核对。

占位就长这样，别美化它：

```
【待补：本鸭的品牌主色 —— 档案里没有这个字段，请你给一个真值】
```

成稿末尾附「素材出处」列表给用户。
→ 两类实证（编造具体值 / 不可核对的通用场景）见 `references/materials.md`。

### 红线二：标题没定，不往下走

出候选 → 用户选定 → 才继续。用户没选就停在这儿等，不许自己挑一个继续写。

### 红线三：标题必须与正文匹配

标题承诺了什么，正文就得兑现什么。标题写「5 个方法」正文只有 3 个 → 自检不通过，改一侧再交付。
标题党（点击高、完读低）会被推荐算法判为低质并降权。

### 红线四：成稿必须先给用户过目

**用户没看过正文之前，绝不进入写进他公众号后台的那一步**——
哪怕他一开始就说了「写完直接推草稿箱」。写进用户自己的号是 `write_external`；平台限流
AI 直出内容，成品链路里必须有一处真实的人类决策。

## 模式 A：写一篇（九步主干）

**九步一口气走完，不要逐步征求同意。** 只在两处停：第 3 步让用户选标题、第 9 步之后问终态。**边界必问，边界内不问。**

请求全由 `scripts/write.mjs` 代发；绕开脚本自己拼请求才读 `dby-gateway/references/protocol.md`。

### 第 1 步 · 读档案 + 拉写作规范（必须早于任何生成动作）

```bash
node scripts/write.mjs prep          # 四样一次拉齐；--json 另带章程全文与 samples[].content
```

四样：**号章程**、**创作 DNA**、**范文样本**（真实细节的合法来源）、**写作规范**（平台硬约束）。
失败脚本已降级处理：401 直接红、**档案为空直接拦下**（先去 `dby-charter` 立定位）、
规范拉不到照常往下走、范文少于 3 篇提醒。

🔴 规范里**硬约束那一节不是建议**，动笔前进上下文；第 5、6、9 步都照它走。

→ 要**封面卡 / 导语**这类「家具」或四样没拉齐时读 `references/writing-spec.md`，不需要就别读。

### 第 2 步 · 确定选题

🔴 **用户已经说了写什么 → 直接用，不要再问，也不要再调接口。**

没说时才取候选：`node scripts/write.mjs topics [赛道]`（不传赛道用档案里的）。
候选要过**号章程**与**有用性门槛**两道筛 —— 判据与打分法读 `references/topic.md`。

### 第 3 步 · 定目标，再定标题（🔴 唯一的中途停顿点）

**先写一行「本篇：目标（涨粉 / 变现 / 常青）/ 素材形态 / 读者意识阶段（无意识 → 问题 → 方案 → 产品 → 最高）/ 人称语气」**，
阶段决定标题答哪个问题；细则与**变现文的 offer 表**读 `references/goals.md`。

**素材形态 = 手里已有什么**（不是"算哪一类"）：带转折的真实经历 / 被访者原话 → **A 组**，
其余（可复现步骤 / 并列多项 / 可核实的具体事件 / 待解释的现象或机制）→ B 组。→ 判别读 `references/goals.md`。

出 **5 个候选**，各过五项自检，**停下来让用户选一个**（也可自己给）。群发后标题只能改 3 个字。

| 检查项 | 通过标准 |
|---|---|
| 完整陈述句 | 单独发给不知情的人，他能复述文章讲什么；15–28 字（**汉字计数，一个英文词算 1 字**，与后台「标题 64 汉字」同口径），核心词在前 15 字 |
| 缺口 | **看本篇目标**：涨粉 / 变现 → 好奇缺口 / 颠覆认知 二选一，正文必须兑现；**常青 → 不强制**，平实陈述句照过 |
| 具体 | 含具体数字优先；禁「让你哭 / 只有 X 才懂 / 测一测」式短语 |
| 受众匹配 | 目标读者一眼认出「这是写给我的」（人群词进标题）——**常青也要过** |
| 搜索适配 | 含读者真会去搜的关键词——**常青尤其要过**（它靠搜索吃长尾） |

🔴 **常青放宽的是「制造缺口」这个手段，不是「让人愿意点」这个目标** ——
谁都不会点的老实标题会卡在「完整陈述句」或「受众匹配」，那两项三种目标一视同仁。

→ 标题写法清单见 `references/craft.md`。

⚠️ 想一遍**转发到朋友圈**：不好意思转的砍掉。

### 第 4 步 · 收素材

按下表从上往下取，够写就停；每条素材进**素材单**（编号 / 原句或数字 / 出处），没进单的不许进正文。

**A 组必须收到第一人称真实经历细节**（时间 / 地点 / 数字），纯观点拼接不被推荐。
**B 组不因缺经历被阻断** —— 它缺的是"内容不够"，标注或缩范围即可。

| 层 | 来源 | 何时用 |
|---|---|---|
| 1 | 用户当轮给的文字 / 链接 / 文件 | 有就先用 |
| 2 | 号档案 + 范文 | 总是（第 1 步已拉到，不再取） |
| 3 | 自己往期文章 | 写过相近题 |
| 4 | 用户知识库（ima / `$DBY_WIKI_DIR`） | 配了才用，没配跳过不问（**A 组例外，见下**） |
| 5 | 平台取数 | 用户点名或前四层不够 —— 🔴 **这一层计费** |
| 6 | 联网查证 | 只核实前面拿到的事实，不引入新数据 |

→ 各层取法与素材单格式读 `materials.md`。

🔴 **A 组六层取完仍拿不到锚点 → 停下，不许开始写正文。** 处置阶梯（问 / 改写法 / 改方向，
以及为什么「先编个通用场景」不在选项里）读 `references/materials.md` 的「锚点收不到时」。

### 第 5 步 · 列提纲

🔴 **先读 `references/genre/<你声明的素材形态>.md`（名字逐字照抄）；没读不列提纲。**
收完素材发现与声明不符 → 改声明、换读那份，别将错就错。

**第一行写一句话中心**（读者带走的那一个想法），指不回它的块删掉。
**每块标注用素材单里的哪几条**（编号）—— 指不上的回第 4 步补，或按红线一留占位。
→ 四种结构、小标题写法、定形状读 `references/craft.md`（**选一种，别混着来**）。

### 第 6 步 · 写正文

**按「块」写，一个一级小标题算一块。** 顺序：先导语 → 再正文 → 最后结尾。开头 150 字内兑现标题。

→ 开头 / 结尾 / 句子级规则与两档重点标记见 `references/craft.md`。
**内容不够时不要扩写，去写细节**——细节只从素材单取（红线一）。

🔴 **硬约束边写边守**，以第 1 步规范为准，**别照记忆里的旧清单写**。

🔴 **口吻按这个号自己的声音写，不是按你的**。`prep` 输出里的两样，动笔前就要用上：
`voiceSystemPrompt`（整段当写作设定）、`taboos`（**一条都不准违反**，写完逐条扫）。
两样为空照常写，交付时说明是通用口吻（去 `dby-charter` 蒸一份）；**别因此停下来问**。

**结尾的行动号召从档案里取**（`productsJson[].ctaScript`；没有就按红线一留占位，**绝不自己编一个背书**）——取法见 `references/craft.md`。

### 第 7 步 · 重写

🔴 **初稿不直接交。** 四步减法（口述摘要重写 / 朗读标打结处 / 先大后小删 /
不确定为真的句子删掉重来）读 `references/craft.md`。

### 第 8 步 · 写摘要与留言

**摘要**按「备用标题」写（别写成正文缩写）。

**留言**（作者给自己文章的第一条留言）**是可选的** —— 不写不影响交付，别记成未完成项。
用户要写、或这篇确实有值得先起个头的话题时才写。
→ 两者怎么写见 `references/craft.md`。

### 第 9 步 · 成稿自检

五件事，一件都不能少：

1. **违禁词与极限词** → 走 `dby-banned-words`，标题 + 摘要 + 正文一起查，只查公众号一个平台。
   **任何终态都要跑。** → 命令行见 `references/api-contract.md`。
2. **广告标识**：正文带购买方式（链接 / 二维码 / 店名）就必须文首标「广告」，没标不交付；
   诱导关注句删。→ 法条与适用范围读 `references/practice.md`。
3. **标题与正文匹配**（红线三）：对照第 5 步那句一句话中心。
4. **事实来源核对**（红线一）：每个细节 / 案例 / 数字 / 品牌事实 / **第一人称场景**逐个指回素材单编号，
   指不回的改占位。🔴 **场景最容易漏** —— 它不含数字也不含品牌名，看着没什么可核对的就被跳过。
5. **平台硬约束逐条对**：按第 1 步规范的「硬约束」小节过一遍；没拉到时如实说「这次没按硬约束核」，**别假装核过了**。

自检过了 → 把成稿**交给用户看**（红线四），只问「哪里看不懂 / 哪里拖」，然后问终态。

## 交棒：问终态

成稿之后**必须问**，不许推断；终态门以 `dby-api/references/wechat-routing.json` 为准：

> 这篇你想要到哪一步？
> ① 就要这份成稿，我自己发 ② 要排版好的公众号 HTML ③ 存进我自己的公众号草稿箱

① 到此为止。
② `dby-publish --render-only`：**渲染免费、不需绑号**。
③ `dby-publish` 完整流水线：**这一步才需已绑号**。
② ③ 先把成稿落盘 `.md`（正文，不含标题）再交棒。
→ 命令行见 `references/api-contract.md`。

回执四行：**查阅 / 执行 / 质检 / 跳过**——没走的步写进「跳过」并说明原因。

## 模式 B：复盘一篇

→ 复盘时读 `references/review-mode.md`（`write.mjs review` 归四象限，**只给一处修复动作**）。
🔴 三条不许简化掉：**写明用的是哪一档指标**（代理档绝不能说成「打开率 × 分享率」）、
**基准只能是这个号自己的历史中位数**、**样本少于 5 篇要把「仅供参考」带给用户**。

→ 用户想练写作、问「怎么提高」时读 `references/practice.md`。
