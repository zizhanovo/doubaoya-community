# 公众号文章写作主干 · dby-write

> 🔀 「写篇文章 / 写个初稿」= **写一篇**（模式 A）；「为什么没人看 / 复盘」= **复盘一篇**（模式 B）。
>
> ⚠️ **已写好的文案**要改平台风格 → `dby-rewrite`；**已写好的正文**只要排版 / 存草稿 → `dby-publish`。

---

## 🔴 四条红线（任何终态下都不许跳过）

### 红线一：事实类内容不许生成

**细节、案例、具体数字、品牌与产品事实（名称 / 颜色 / 价格 / 功能 / 承诺）
只许来自素材单里有出处的条目**（第 4 步收的）。

素材单里没有时，**留一个显式占位并告诉用户需要补什么**，
绝不用一个看起来合理的值填上去。（实证：曾把品牌主色编成 `#15785A`，真值是 `#FF8708`。）

占位就长这样，别美化它：

```
【待补：本鸭的品牌主色 —— 档案里没有这个字段，请你给一个真值】
```

成稿末尾附「素材出处」列表给用户。

### 红线二：标题没定，不往下走

出候选 → 用户选定 → 才继续。用户没选就停在这儿等，不许自己挑一个继续写。

### 红线三：标题必须与正文匹配

标题承诺了什么，正文就得兑现什么。标题写「5 个方法」正文只有 3 个 → 自检不通过，改一侧再交付。
标题党（点击高、完读低）会被推荐算法判为低质并降权。

### 红线四：成稿必须先给用户过目

**用户没看过正文之前，绝不进入写进他公众号后台的那一步**——
哪怕他一开始就说了「写完直接推草稿箱」。写进用户自己的号是 `write_external`；平台限流
AI 直出内容，成品链路里必须有一处真实的人类决策。

## 模式 A：写一篇（九步主干）

**九步一口气走完，不要逐步征求同意。** 只在两处停：第 3 步让用户选标题、第 9 步之后问终态。**边界必问，边界内不问。**

请求全由 `scripts/write.mjs` 代发；绕开脚本自己拼请求才读 `dby-gateway/references/protocol.md`。

### 第 1 步 · 读档案 + 拉写作规范（必须早于任何生成动作）

```bash
node scripts/write.mjs prep          # 四样一次拉齐；--json 另带章程全文与 samples[].content
```

四样：**号章程**、**创作 DNA**、**范文样本**（真实细节的合法来源）、**写作规范**（平台硬约束）。
失败脚本已降级处理：401 直接红、**档案为空直接拦下**（先去 `dby-charter` 立定位）、
规范拉不到照常往下走、范文少于 3 篇提醒。

🔴 规范里**硬约束那一节不是建议**，动笔前进上下文；第 5、6、9 步都照它走。

→ 要**封面卡 / 导语**这类「家具」或四样没拉齐时读 `references/writing-spec.md`，不需要就别读。

### 第 2 步 · 确定选题

**用户已经说了写什么 → 直接用，不要再问，也不要再调接口。**

用户没说时才取候选：

```bash
node scripts/write.mjs topics [赛道]      # 不传赛道则用档案里的
```

候选用号章程筛：够不够热、人设的真实视角接不接得住；**接不住的再热也放掉**。

**有用性门槛**（用户给的题也过）：**对吗 × 重要吗（多少人 × 多在乎）× 读者不知道吗 × 能说多硬**，
各打 0–3 分相乘，任一为 0 就换题；新颖点去**流行但错误的常识旁边**找。

→ 用户说「参考同题材的爆款」时读 `references/hot-samples.md`（计费）。

### 第 3 步 · 定目标，再定标题（🔴 唯一的中途停顿点）

**先写一行「本篇：目标（涨粉 / 变现 / 常青）/ 读者意识阶段（无意识 → 问题 → 方案 → 产品 → 最高）/ 人称语气」**，
阶段决定标题答哪个问题；细则读 `references/goals.md`。**变现文先出「事实 → 利益 → offer」表再写标题。**

出 **5 个候选**，各过五项自检，**停下来让用户选一个**（也可自己给）。群发后标题只能改 3 个字。

| 检查项 | 通过标准 |
|---|---|
| 完整陈述句 | 单独发给不知情的人，他能复述文章讲什么；15–28 字，核心词在前 15 字 |
| 缺口 | **好奇缺口 / 颠覆认知 二选一**，正文必须兑现；「人人已知」的砍 |
| 具体 | 含具体数字优先；禁「让你哭 / 只有 X 才懂 / 测一测」式短语 |
| 受众匹配 | 目标读者一眼认出「这是写给我的」（人群词进标题） |
| 搜索适配 | 含读者真会去搜的关键词 |

→ 标题写法清单见 `references/craft.md`。

⚠️ 想一遍读者**转发到朋友圈的场景**：不好意思转的标题砍掉。

### 第 4 步 · 收素材

按下表从上往下取，够写就停；每条素材进**素材单**（编号 / 原句或数字 / 出处），没进单的不许进正文。
必须收到**第一人称真实经历细节**（时间 / 地点 / 数字），纯观点拼接不被推荐。

| 层 | 来源 | 何时用 | 怎么取 | 计费 |
|---|---|---|---|---|
| 1 | 用户当轮给的文字 / 链接 / 文件 | 有就先用 | 直接用；链接抓不到再 `tool.content.parseDetail` | 后者计费 |
| 2 | 号档案 + 范文 | 总是 | 第 1 步已拉到，不再取 | 免费 |
| 3 | 自己往期文章 | 写过相近题 | `node scripts/write.mjs articles [--q 关键词] [--id 序号]` | 免费 |
| 4 | 用户知识库（ima skill / `$DBY_WIKI_DIR`） | 配了才用，没配跳过不问 | `ima-skills` 检索；`rg -il 词 "$DBY_WIKI_DIR" --glob '*.md'` | 免费 |
| 5 | 平台取数（`api.gzh.hotArticle` / `api.trend.hotSpotKeyword`） | 用户点名或前四层不够 | 走 `dby-api` | 计费 |
| 6 | 联网查证 | 只核实前面拿到的事实 | 宿主搜索工具；不引入新数据 | 免费 |

→ 各层取法与素材单格式读 `references/materials.md`。

### 第 5 步 · 列提纲

**第一行写一句话中心**（读者带走的那一个想法），指不回它的块删掉。
→ 四种结构见 `references/craft.md`，**选一种，别混着来**；块与块是问答关系（上一节末的问题下一节答）。

**小标题 = 论点，每个小标题下先列关键词 = 论据，并标注这一块用素材单里的哪几条**（编号）。
指不上素材的块回第 4 步补，或按红线一留占位。至少一块是读者能转述给别人的实用价值。

定形状：按规范「什么内容写成什么结构」标出哪块是有序列表 / 表格 / 引用块。

### 第 6 步 · 写正文

**按「块」写，一个一级小标题算一块。** 顺序：先导语 → 再正文 → 最后结尾。开头 150 字内兑现标题。

→ 开头 / 结尾 / 句子级规则与两档重点标记见 `references/craft.md`。
**内容不够时不要扩写，去写细节**——细节只从素材单取（红线一）。

🔴 **硬约束边写边守**，以第 1 步规范为准，**别照记忆里的旧清单写**。

🔴 **口吻按这个号自己的声音写，不是按你的**。`prep` 输出里的两样，动笔前就要用上：
`voiceSystemPrompt`（整段当写作设定）、`taboos`（**一条都不准违反**，写完逐条扫）。
两样为空照常写，交付时说明是通用口吻（去 `dby-charter` 蒸一份）；**别因此停下来问**。

**结尾的行动号召从档案里取**（`productsJson[].ctaScript`；没有就按红线一留占位，**绝不自己编一个背书**）——取法见 `references/craft.md`。

### 第 7 步 · 重写

初稿不直接交：① 凭记忆只写关键点**口述摘要重写** ② **朗读**，标出打结的句子，自己不想读的段落整段删
③ 减法先大后小：删无关整段 → 合并同质观点 → 逐句删累赘词 ④ **不确定为真的句子删掉重来**。细则见 `references/craft.md`。

### 第 8 步 · 写摘要与留言

**摘要**按「备用标题」写（别写成正文缩写），**留言**是作者给自己文章的第一条留言。
→ 怎么写见 `references/craft.md`。

### 第 9 步 · 成稿自检

五件事，一件都不能少：

1. **违禁词与极限词** → 走 `dby-banned-words`，命令写死一个平台，标题 + 摘要 + 正文一起查：
   `python3 <dby-banned-words>/scripts/check_multi.py "<标题+摘要+成稿>" --platforms gongzhonghao`（任何终态都要跑；只查公众号）
2. **广告标识**：知识介绍 / 体验分享 / 测评 + 购买方式（链接 / 二维码 / 店名）= 文首显著标「广告」
   （《互联网广告管理办法》第九条），没标不交付；「点在看 / 关注才能…」诱导句删。
3. **标题与正文匹配**（红线三）：对照第 5 步那句一句话中心。
4. **事实来源核对**：每个细节 / 案例 / 数字 / 品牌事实逐个指回素材单编号，指不回的改占位（红线一）
5. **平台硬约束逐条对**：按第 1 步规范的「硬约束」小节过一遍；没拉到时如实说「这次没按硬约束核」，**别假装核过了**。

自检过了 → 把成稿**交给用户看**（红线四），只问「哪里看不懂 / 哪里拖」，然后问终态。

## 交棒：问终态，再决定走多远

成稿之后**必须问**，不许推断；终态门以 `dby-api/references/wechat-routing.json` 为准：

> 这篇你想要到哪一步？
> ① 就要这份成稿，我自己发 ② 要排版好的公众号 HTML ③ 存进我自己的公众号草稿箱

② ③ 都先把成稿落盘成 `.md`（正文，不含标题），再交棒。
① 到此为止，不跑 `dby-publish`；② 交棒 `dby-publish`，用 `node scripts/pipeline.mjs --md 稿子.md --title "标题" --render-only`
（🔴 渲染免费、**不需要绑公众号**）；
③ 交棒 `dby-publish` 跑完整流水线，`node scripts/pipeline.mjs --md 稿子.md --title "标题" --digest "<摘要>"`
（**那一步才需要已绑号**）。第 8 步的留言流水线没有地方放，随成稿交给用户手动贴。

回执随交付写，四行：**查阅 / 执行 / 质检 / 跳过**——按终态没走的那步写进「跳过」并说明原因。

## 模式 B：复盘一篇

→ 复盘时读 `references/review-mode.md`（`write.mjs review` 归四象限，**只给一处修复动作**）。
🔴 三条不许简化掉：**写明用的是哪一档指标**（代理档绝不能说成「打开率 × 分享率」）、
**基准只能是这个号自己的历史中位数**、**样本少于 5 篇要把「仅供参考」带给用户**。

→ 用户想练写作、问「怎么提高」时读 `references/practice.md`。
