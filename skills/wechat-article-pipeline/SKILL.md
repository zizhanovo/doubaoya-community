# 公众号图文全链路（都爆鸭）

用户说「帮我写篇公众号文章 / 写完发出去」，从这里开始。本 Skill 是**编排者**：它不替你记
每条接口长什么样，只回答两件事——**这一步该用哪条能力**，以及**什么时候该停下来问人**。

正文由**你（agent）自己写**，平台不代写；平台负责查热点、查违禁词、生图、排版、写进草稿箱。

---

## 0. 先定终态，别一路推到底

这条链有**三个合法的停手位**，用户要的是哪一个，决定你走到第几步：

| 用户要的终态 | 走到 | 之后 |
|---|---|---|
| ① 只要一篇**成稿**（Markdown 就行） | 第 3 步（写完 + 过合规）就收手 | 把稿子交给用户，**别自作主张往下发** |
| ② 要**排版好的公众号 HTML** | 第 5 步 | 把 HTML 交给用户 |
| ③ 要**文章进自己公众号草稿箱** | 第 6 步 | 让用户去后台亲眼确认，**群发的手始终在他自己** |

> 🔴 **用户没说清是哪一档，先问一句再动手。** 第 6 步会写进他自己的公众号后台，第 4 步会扣点数——
> 这两件事都不该由你替他决定。只要 ① 的时候不跑第 5、6 步**是正确行为，不是漏跑**。

**只存草稿，绝不群发。** 本 Skill 全程没有任何群发路径，也不接受任何群发参数。

## 1. 选题：查热点 / 找对标（可选，但用户说「先查热点」就必须做）

| 想要什么 | 用哪条能力 | 详情端点 |
|---|---|---|
| 全网正在热什么（跨平台热榜） | `api.trend.hotTopics` | `GET /api/apis/trend/hot-topics` |
| 这个题在公众号里有没有爆过（对标样本） | `api.gzh.hotArticle` | `GET /api/apis/gongzhonghao/hot-article` |

**结果怎么用**：热榜只给你**信号**，不给你选题。把返回里跟用户话题真正相关的那几条挑出来，
折成 2–3 个**具体角度**（谁的痛点 + 什么冲突 + 什么结论），让用户挑一个再动笔；
一条都不相关就如实说「这个题当下没蹭到热点」，照用户原意写，别硬凑。

> 🔴 **广域搜索类永远「有结果」，所以每一次重试都是一次真实扣费。** 换个关键词再试一次不是免费动作。
> 先按协议第 2 条把入参拿准，再打第一枪。**用户已经给了话题，第一枪就把话题带上**——
> 先打一枪不带话题的「看看全网在热什么」，拿回来的必然是一堆跟他无关的泛热榜，那一枪纯属白烧
> （实测就这么烧掉过一次全价查询）。拿到空结果时别急着判「上游挂了」——已经因此误判过两次，
> 真因都在入参上（一次时间参数没给对，一次分类名必须写全称）。

## 2. 动笔前：拉一份写作规范

```bash
curl -sS https://doubaoya.com/api/wechat/writing-spec -H "Authorization: Bearer $DOUBAOYA_API_KEY"
```

**只读、免费、不扣点**，也不改用户任何配置。响应里带一段 markdown 写作规范——**要照着写的就是它**，
它把「什么内容该写成什么 markdown 结构」和「平台会整篇打回 / 静默丢内容的硬约束」写成了可直接照做的文字。
具体有哪些字段**照这一次的实际响应读**，别照记忆读。

- 拿到 **401** = 密钥缺失或不对，提示用户检查，**别跳过**。
- 只有**网络错误或真 404** 才降级：跳过这一步照常写（本文件的写作红线已经够用），别死循环重试、别当故障报。
- 规范里「本主题的呈现」那部分，只在这篇**真用服务端排版渲染**时成立（见第 5 步）；
  「结构建议 + 平台硬约束」那部分**永远成立**。

## 3. 写正文（你自己写）+ 过合规

### 🔴 正文不要写标题

公众号**总是**拿草稿的标题字段渲文章页大标题。正文里若还有同一个标题，真机上**显示两次**。

- 写 Markdown：正文**从第一段直接开始**，层级最高只用到 `##`。
- 直接交付 HTML：别在开头放 `<h1>`（或拿来当大标题使的 `<h2>` / 加粗大字）。

### 质量标准（够不到就别交）

- 有具体的人、事、数，不是一篇「关于某话题的综述」；
- 每个 `##` 小节只讲一件事，读者能一口气读完；
- 结论落在**用户能拿去做的事**上，不是「让我们拭目以待」。

### 合规：写完必须过一遍违禁词

| 用哪条能力 | 详情端点 |
|---|---|
| `skill.wechat.prohibitedWord` | `GET /api/skills/wechat-prohibited-word` |

> 🔴 **点名违禁词能力时必须连详情端点一起给。** `tool.contentSafety.checkWords` 这个 operationKey
> **同时存在于两个集合**（`/api/apis/tool/check-banned-words` 与 `/api/skills/content-safety-check`），
> 是全平台唯一一处撞名——只报 operationKey 不足以定位，会打到另一条路由上。

**结果怎么用**：照**这一次的实际响应**读它到底回了什么，逐条对着正文改。

- 🔴 **别去读响应里没有的东西，更别自创一套「等级」糊弄用户。** 照一个不存在的字段判「它是空的 ⇒ 文案合规」，
  那是个**恒真判据**，会把每一段文案都放行——这是安全缺陷，不是体验问题。
- **「一个都没查出来」是一个有效答案，照常计费**，不会被标成无结果。别把它当失败重试。

## 4. 封面与配图（💰 花钱，动手前必须先问用户）

| 想要什么 | 用哪条能力 | 详情端点 |
|---|---|---|
| 按爆款封面套路做一张公众号封面 | `skill.wechat.coverDesign` | `GET /api/skills/wechat-cover` |
| 自由文生图 / 按参考图生图（封面、正文配图） | `skill.ai.imageGen` | `GET /api/skills/gpt-image-gen` |

**引导是默认**：先把封面概念（主体 + 氛围）讲给用户听，他点头再生。用户说「你全权定 / 我赶时间」
才是跳过停顿的逃生舱。

- **封面必须防裁切**：公众号按 2.35:1 居中裁，主体压在水平中带、上下留氛围背景，否则关键内容被切掉。
- **配图落进 Markdown 源**（不是渲染后的 HTML）——放进源里才会被主题套上图注 / 圆角 / 间距，
  落完回第 5 步重渲染。
- 想点着选、而不是逐轮描述 → 起本地设计工作台，见 [`references/local-tools.md`](./references/local-tools.md) 第 6 节。

## 5. 排版

| 用哪条能力 | 详情端点 |
|---|---|
| `skill.wechat.render` ⚠️专用路由 | `GET /api/skills/wechat-render` |

⚠️ **专用路由的调用地址跟详情端点毫无关系，推不出来**——只能读详情响应里 `execution` 的 `target`
（协议第 3 条）。误走通用 `/invoke` 会 400 `DEDICATED_ROUTE`。

**什么时候不走它、改用本地渲染器**：正文里用了 `:::关注卡` / `> [!TIP]` 这套组件语法，
或者用户没有密钥、只想先看看排出来什么样。两条路的真实分叉写在
[`references/local-tools.md`](./references/local-tools.md) 第 1、4 节。

## 6. 存进草稿箱（🔴 会写进用户自己的公众号后台）

| 用哪条能力 | 详情端点 |
|---|---|
| `skill.wechat.draftPublish` ⚠️专用路由 | `GET /api/skills/wechat-draft-publish` |

**动手前的硬门**，一条不过就停：

1. 用户**明确要**终态 ③（见第 0 节）——没说过就先问；
2. 目标账号确认过：他在 doubaoya.com 绑的是哪个公众号、要发到哪个（绑了多个就让他挑）；
3. 正文里**没有本机图片**。有的话服务端读不到你本机的文件，**必须先在本地把图传上去**——
   走 [`references/local-tools.md`](./references/local-tools.md) 第 1、2 节，那是平台能力办不到的活。

**存完怎么回报**：标题 / 公众号昵称 / 正文图上传数 / 封面（自己的 or 兜底）/ 草稿标识 /
**群发：否**。然后请用户去公众号后台亲眼确认排版、封面、图片都对，再由他自己手动群发。

## 调用都爆鸭（协议，抄自 `doubaoya-gateway`）

**本 Skill 用到的能力**（只点名能力和详情端点；入参**不在这里写**，每次调用前现拉）：

| operationKey | 详情端点 |
|---|---|
| `api.trend.hotTopics` | `GET /api/apis/trend/hot-topics` |
| `api.gzh.hotArticle` | `GET /api/apis/gongzhonghao/hot-article` |
| `skill.wechat.prohibitedWord` | `GET /api/skills/wechat-prohibited-word` |
| `skill.wechat.coverDesign` | `GET /api/skills/wechat-cover` |
| `skill.ai.imageGen` | `GET /api/skills/gpt-image-gen` |
| `skill.wechat.render` ⚠️专用 | `GET /api/skills/wechat-render` |
| `skill.wechat.draftPublish` ⚠️专用 | `GET /api/skills/wechat-draft-publish` |

1. **鉴权**：所有*调用*端点都要 `Authorization: Bearer $DOUBAOYA_API_KEY`。
   优先从环境变量 `DOUBAOYA_API_KEY` 读；环境里没有就**问用户一次**，之后不再追问。
   🔴 **一个字符都不许回显、打印或写进日志——前缀也是密钥内容。** 要报状态只许说
   「已设置 / 没设置」，别打印任何截断形式（`${KEY:0:6}` 这种写法就是在打印密钥）。
   基址 `https://doubaoya.com`。
2. **先拉规格，再拼参数**：`GET <详情端点>`（免鉴权、免费）。按 `inputContract` →
   `inputUiSchema` 的 `fields` → `requestSchema`（示例值，非规格）的顺序取，**就近取到就停**。
   🔴 **绝不照记忆或本文档里的字段名拼入参**——这里从来不写字段名，就是为了让你没得抄。
3. **照 `execution.target` 打，别自己拼地址**：同一个详情响应里有
   `execution.target.method` 和 `execution.target.path`，前面拼上基址就是要打的地址。
   `execution.mode` 为 `dedicated` 时方法未必是 `POST`（有 `PUT`）；为 `unavailable` 时
   **没有 `target`，别调**，如实告诉用户这条能力暂时不可用。
4. **两条路由互不回落**：`/api/skills/<slug>/invoke` 与 `/api/apis/<platform>/<slug>/call`
   是**两个不相交集合**各自的入口，拿错集合的 slug 去打另一条一律 404，**换着花样重试没有用**。
   所以第 3 条不是建议：地址只能来自详情响应。
5. **读信封**：成功失败都是同一层 `{ success, requestId, data, error }`。
   **先看 `success`**——`true` 取 `data`，`false` 读 `error.code` / `error.message`。
   成功信封上还可能多出三个可选字段（**缺席是常态，不是异常**）：
   - `noResult`：查询合法、就是没数据，**已不计费**。别当失败重试，如实告诉用户没结果并建议换条件。
   - `notice`：本 Skill 有更新的提示，**原样转达**，不影响本次结果。
   - `detailUrl`：这次结果在 doubaoya.com 上的详情页，可以给用户点。
6. **报错怎么办**（`HTTP` / `error.code`）：
   401 `MISSING_API_KEY` / `UNAUTHORIZED` → 让用户去密钥中心生成或重建，更新环境变量；
   400 `VALIDATION_ERROR` → 照 `message` 改入参，改前**重拉一次规格**；
   400 `DEDICATED_ROUTE` → 走错到通用代理了，`message` 里写着该打哪条，照 `execution.target` 重发；
   402 `INSUFFICIENT_CREDITS` → 提示用户充值；
   404 `SKILL_NOT_FOUND` / `ENDPOINT_NOT_FOUND` → 见第 4 条，**去另一个集合的发现接口找**，别猜 slug；
     发现接口里也没有这条能力时，**多半是本机 skill 已经过期**（它点名的能力早就下架了）：
     跟用户说一句「你的本鸭 skill 可能过期了」，让他跑一次 `/dby-update`（或说「更新都爆鸭」），
     然后**只重试这一次**。🔴 重试仍是 404 就如实告知能力已下架，**不许再更新、不许成环**。
   503 `CAPABILITY_UNAVAILABLE` → **别重试**，换能力或如实告知；
   502 `PROVIDER_FAILED` → 上游临时失败，**额度已自动退回**，可以直接重试。
   🔴 只有上面这条 404 走「先更新再重试」，**别的错一律不许触发更新**——
   401 是钥匙问题、400 是入参问题、402 是余额问题，更新 skill 一个都治不了，
   把它们也当成「该更新了」只会让每次失败都多跑一遍安装。

### 什么时候去读 `doubaoya-gateway`

上面这段协议是**完整的**，照它就能把每一次调用打出去，正常流程里不必再读别的。
只有这两种情况去读网关那个 Skill：

| 情况 | 读哪份 |
|---|---|
| 用户要的东西不在上面那张表里（换个平台、要账号诊断、要别的榜单），你得先知道有哪条能力 | `doubaoya-gateway` 的 `references/capability-index.md`（**只供选路**，不含入参） |
| 选定能力之后、真正打请求之前，想确认这条有没有已知的坑 | `doubaoya-gateway` 的 `references/routing-pitfalls.md` |

🔴 **别把索引表整段抄回本文件。** 本 Skill 只点名自己用的那七条；能力目录一周就变一次，
抄进来的当天就开始腐烂——那正是本形态要根治的病。

## 需要本机文件时：`references/local-tools.md`

有三件事平台能力**天然办不到**，必须落到用户本机：**正文里的本机图片**（服务端读不到）、
**无密钥的本地排版预览**、**复刻某篇文章的排版**。这三件事的脚本、CLI、主题写法全在
[`references/local-tools.md`](./references/local-tools.md)——**用到才读，别一上来就读**。

判据只有一条：**这一步要读写用户本机的文件吗？** 要 → 本地脚本；不要 → 走上面的协议。

## 下一步（草稿存好之后）

草稿进箱，用户「要一篇能发的公众号图文」这个终态就达成了——**这里通常就是终点**。
**群发的手始终在用户自己**：本 Skill 没有任何群发路径，请他去公众号后台确认再手动群发。

| 用户接着想要什么 | 下一步 |
|---|---|
| 攒几天数据后看这个号的发文表现 / 做体检 | `wechat-account-analyzer` |
| 盯自己或竞品的发文节奏 | `doubaoya`（打公众号发文列表端点） |
| 把已发布的文章拉正文归档 | `content-parse` |
| 想把默认排版改成自己的样子 | `wechat-theme-studio` |
| 用复盘信号挖下一轮选题 | `doubaoya`（挖选题 / 追热点）或 `wechat-hot-write`（拉样本开写） |
| 说不清要到哪一步 | `dby`（公众号飞轮的逐跳导航） |
